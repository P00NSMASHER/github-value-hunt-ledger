# CAPABILITIES

Canonical capability-level synthesis. A repository is not a capability: a capability is a reusable, falsifiable ability supported by source/tests/data and bounded by explicit limitations. Detailed repository evidence remains in MASTER, COMPONENTS, DATASETS and hunter catalogs.

## Capability schema
Each CAP records ability, maturity, evidence basis, reusable targets, limitation, missing piece and next falsifiable test. Repository-code commercial permission does not extend to third-party data, standards, patents, trademarks, vendor services or customer records.

## Capability promotion rule
Add/update a CAP only when the system can state a falsifiable ability, evidence basis, limitations and next test. Repositories may remain strong components without creating a new CAP.

## Strategic KPI
Optimize for capabilities reused across products, independent tests survived, experiments completed, build-time compression actually observed and realized customer value/revenue — not repository count.
