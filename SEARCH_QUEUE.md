# SEARCH_QUEUE

Integrator-owned search and validation direction. Updated 2026-09-20. **Experiment bottlenecks, independent falsification, source authority and outcome evidence now outrank broad repository collection.** Search only when a concrete missing capability/evidence edge remains. Prefer repository families, old product names, protocol/standard signatures, unusual classes/files, dependency/fork/commit/PR lineage, paper↔code lineage and obscure low-attention implementations.

## Operating rules for all 14 workstreams
- Deduplicate by **repository + exact revision + capability**.
- Use the user's standing separate commercial-permission assertion for repository-owned public code/content; record actual public license/provenance and keep third-party datasets, standards, model weights, patents, trademarks, APIs/services and customer records separately governed.
- Verify beyond README with implementation source, tests, schemas/migrations, fixtures, deployment/config and history.
- Never inspect/retain/test/use credentials, auth material, private/personal/confidential data, accidental secrets or unauthorized-access material. Sanitized metadata only.
- Reuse benchmark-supported skills when applicable: first-party production-source triangulation; ingestion invariant-triad intersection; acceptance-path transition inspection; fail-open boundary archaeology; decision-claim → runtime-side-effect trace; authority-origin/invariant-set consistency; rule-period/authority-version audit.
- Before declaring an important no-find, perform one **recall-oriented rescue pass** using repo-family/old-name/author-org adjacency, oracle/test-fixture vocabulary and near-match lineage. Do not loosen the verification gate.
- Any PASS/VERIFIED state must survive missing/stale/ambiguous evidence, parser/environment failures, empty-success states and selection fallbacks.
- Any decision claim must trace **public dispatch → executable body → meaningful side effect → semantic test**.
- Any money/trust claim must identify who authored/authorizes each input and ensure rejected/unknown evidence cannot re-enter totals, billing, health or proof summaries.
- Any effective-dated rule must pin exact authority, effective/supersession periods and load-bearing thresholds/exceptions; repo recency is not substantive currentness.
- No padding. A no-new-find run is acceptable.

## 14. Sparse-lane repair + wildcard analog search — P2
Keep under-filled catalogs productive with narrow analogs:
- finance/AP: source authority → expected → invoice/credit → settlement;
- insurance/claims: entitlement/recovery with current rule authority + outcome;

After five weak runs from a query family, record the failure pattern and rotate to dependency, author/lab, commit/PR, standard/protocol or old-product-name archaeology rather than repeating keywords.
