CLAIMS VERIFIED: Multi-system connector dispatch is implemented for Socrata, ArcGIS, CKAN and HTML/Accela-style sources, with connector configuration stored per jurisdiction. `PermitVersion` is an append-only audit table with full snapshots, monotonically unique `(permit_id, version_number)`, and `changed_fields` old/new diffs; the ingest path writes a version for create/update and explicitly canonicalizes datetimes to avoid false version churn. Regression tests reproduce same-batch duplicate permit-number collisions and require sequential gap-free versions. Semantic mapping QA is real rather than aspirational: live source schemas were audited field-by-field and the repo documents/fixes concrete money-relevant errors (Chicago permit fee misread as valuation, Austin missing valuation fields, Tempe fee-vs-project-cost, contact-role misclassification, SF completion-date source), with regression tests asserting those semantics. Commit history shows the versioning race was found and fixed after scaling; a recent commit reports 538,981 ingested permits across 62 jurisdictions. Public GitHub metadata reports zero stars and no root public license metadata. RED-TEAM/VERIFIER verdict: STRONG for the benchmark target because the three defining invariants are evidenced in source/tests/history, not merely README claims.
CLAIMS NOT VERIFIED: No independent live run of the full 538,981-row corpus was performed in this benchmark; reported scale is commit-history/repository evidence. Postgres/PostGIS production behavior is not fully proven here; the repo's own blocker notes say local operation was SQLite-first, Redis/Celery execution was untested in that environment, and PostGIS-specific query behavior was not implemented/tested there. Accela and some municipal data access can depend on agency agreements or portal availability. No root public license is published; per the hunt's standing authorization this does not block repository-code prioritization, but third-party municipal data/API terms remain separate. The repository contains a documented path referencing prior browser-automation signup evidence that may contain sensitive profile data; that directory was deliberately not opened or inspected.
STRONGEST OBJECTION: It is a very young, partly scaffolded product with production-infrastructure gaps, no public license metadata, and access/legal friction for some municipal sources. Its strongest evidence is the ingestion/versioning/mapping kernel, not a fully proven nationwide production SaaS. The correct use is therefore to treat it as the ingestion/provenance core, not assume every acquisition path or deployment surface is production-ready.
COMMERCIAL WEDGE: A paid Permit Feed Reliability / Property Intelligence Ingestion service for contractors, suppliers, lenders, insurers, investors, or existing property-data vendors: onboard a metro, ingest and normalize permits, preserve every revision with queryable old/new diffs, run semantic mapping QA, and deliver high-confidence change alerts with raw-source provenance. Money path is faster jurisdiction launch, fewer silent schema-drift/mapping errors, reduced connector engineering, and more defensible lead/history data. Use PermitBuild's connector + append-only version/diff + regression-QA kernel; harden deployment/source-health SLAs separately and pair with broader connector ecosystems only where they improve coverage without weakening provenance.

FALSE-PROMOTION RISK: Low-to-moderate. The core benchmark requirements are unusually well evidenced, but repository-reported scale and production-readiness claims were not independently reproduced; deployment/access rights remain the main over-promotion risk.
LESSON: Distinctive durability/semantic signatures (`permit_versions`, `changed_fields`, fee-vs-valuation regression, duplicate permit-number version races, field-completeness audits) were far more discriminative than generic “permit intelligence” repository names. For ingestion-plane hunts, first search for connector families + explicit historical-state primitives + domain-error regression language, then red-team whether history is truly append-only and whether mapping QA catches semantic—not just syntactic—drift.
