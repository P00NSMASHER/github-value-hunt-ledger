# Pair 6 — EXPERIMENT persistent state

## Validated reusable lessons
- Task 37: For heterogeneous ingestion systems, the strongest evidence is the conjunction of connector implementation + historical-state invariants + semantic regression tests. Provider count alone is insufficient: `PermitBuild` became strong only after source/tests showed append-only `PermitVersion` snapshots, old/new field diffs, monotonic version numbering, and mapping regressions for domain errors such as permit-fee-vs-project-valuation confusion.
- Task 37: Red-team the difference between a broad connector plane and an evidence-grade history plane. `urban-signal` demonstrated a much broader multi-platform municipal ingestion ecosystem and extensive per-city field-map contract tests, but an equivalent immutable permit-version/diff model was not established during this task; breadth should not substitute for the missing target invariant.
- Task 38: The same provider + temporal-evidence + run-health decomposition generalized to government acquisition forecasts. Generic GovCon searches were noisy, while independent symbol searches for source families (`gsa_gateway`, `dhs_apfs`, `state_forecast`), temporal primitives (`first_seen_at`, `history`, `changes`) and run-state semantics (`success`, `partial`, `failed`) converged on `davidlarrimore/curatore-v2`.
- Task 38: Do not accept a `history` field as proof of usable change intelligence. Trace the read path to the actual diff algorithm. In `curatore-v2`, `ForecastService.get_forecast_history()` calls `_compute_history_changes()`, which compares consecutive snapshots and classifies fields into added, removed and modified `{from,to}` values; the CWR primitive exposes those diffs alongside first-seen/last-updated timestamps.
- Task 38: Source-run enums are not sufficient proof of trustworthy feed health. The outer forecast task correctly distinguishes success/partial/failure from processing/error counts, but the APFS fetcher can turn an unexpected response shape into an empty list without raising, creating a false-green zero-record success path. Red-team ingestion systems for empty-success and parser-suppression states.
- Task 38: Identity design is part of version-history correctness. The State connector intentionally excludes volatile fields such as estimated value from row identity and semantic history to reduce false churn, but its title + NAICS + fiscal-year identity can still split continuity if the title itself changes.
- Task 38: Absence of a dedicated domain regression suite should cap evidence quality even when source/schema/migrations are strong. The pinned `backend/tests` tree contains no forecast-specific regression file, so capability existence is strong but production reliability remains less proven.
- Task 39: For virtual-commissioning/industrial-simulator searches, generic `OPC UA simulator` queries mostly surface manually defined signal servers. The high-value discriminator is the conjunction of (1) import of a controller engineering artifact, (2) vendor-specific canonical address/namespace semantics, and (3) executable fidelity tests for difficult constructs. `Gaskony-Ignition/module-plc-emulator` cleared all three: supported L5K import, Rockwell `Program:`/member/array/BOOL packing policy, and extensive address-space fidelity tests.
- Task 39: Verify namespace fidelity at the generated node layer, not from screenshots or feature tables. `RockwellLogixPolicy` and `AddressSpaceBuilder` make the contract concrete in NodeIds and typed Milo nodes; the fidelity suite asserts both positive paths and negative paths (for example old `Programs.` forms and bare BOOL-array element nodes must not exist). Negative assertions were especially useful for distinguishing real driver compatibility from merely plausible hierarchy rendering.
- Task 39: Parser history can be evidence of maturity when it records concrete semantic failures and removes unsupported surfaces rather than masking them. The v10.1 L5K rewrite explicitly addressed ladder-rung text being misparsed as tags, added block-bounded/fail-loud parsing, and v11 withdrew user-facing L5X because it was not live-verified. That is stronger evidence than claiming broad format support without regression proof.
- Task 39: Strong implementation evidence still needs deployment calibration. The deepest address-space fidelity suite is opt-in, environment-gated real-site L5K tests are not public-CI reproducible, and documented gaps remain for motion member sets, integer bit addressing, structure-member initial values, alias target typing and hot-reload continuity. These should cap production-readiness claims even when the benchmark target itself is strong.
- Task 40: For official protocol-stack/pre-FAT searches, implementation breadth alone is insufficient. The useful intersection is first-party reference implementation + explicit migration contract + executable reconnect/subscription regression corpus. `OPCFoundation/UA-.NETStandard` cleared all three with official client/server stack provenance, a 1.5.378→2.0 migration guide/analyzer, connection-state tests, subscription transfer/republish tests and a dedicated audit-regression corpus.
- Task 40: Commit archaeology can yield a reusable defect taxonomy that is more commercially useful than feature documentation. Commit `ea93c86da2dbf0a98568be30c96242d9a2c7d37a` records a read-only client audit that fixed 78 defects and added 35 regression tests across reconnect cancellation, partial subscription transfer, snapshot/restore, SetTriggering bounds, republish-gap walking, client-handle collision, queue-size ratcheting and state-format versioning.
- Task 40: Search issues newer than the pinned revision before making industrial/protocol readiness claims. Open issue #4508, filed after pinned head `37b5522...`, describes a destructive-server-restart deadlock in V2 subscription recreation where quiesce/drain waits on workers that themselves wait for reconnect. This does not invalidate the stack as a reference/migration oracle, but it caps claims that the newest V2 path is universally production-safe and creates a mandatory pre-FAT adversarial scenario.
- Task 40: Separate official/conformance authority from version-specific operational readiness. Certification and first-party provenance strengthen protocol correctness evidence, but they do not eliminate fast-moving implementation defects in a preview branch.
- Task 41: In usage billing, idempotent push is not parity. Require an independent provider read-back path and trace the exact local-counter→provider-summary→persisted-drift execution path. `geminimir/meterguard` cleared this existence test with local counters, Stripe `listUsageRecordSummaries`, persisted local/Stripe totals, epsilon-based status and adjustment workflow.
- Task 41: Red-team repair directionality. In MeterGuard, Stripe>local produces pending positive local adjustments, while local>Stripe only alerts for manual intervention. That asymmetry is safer than silent bidirectional mutation but proves a workflow, not that the provider is authoritative. A strong reconciliation candidate should make source-of-truth and repair governance explicit for each direction.
- Task 41: Executable demo consistency is independent evidence. The current parity workflow is stale: its Ubuntu action invokes a seed script using BSD/macOS `date -v`, and the scenario calls the reconciliation summary endpoint without currently required `periodStart`/`periodEnd`. A polished parity demo can therefore fail as a verifier even when the underlying kernel exists.
- Task 41: Provider API lifecycle is part of reconciliation correctness. The pinned driver uses `stripe ^14.25.0` legacy UsageRecord APIs; current stripe-node removed those methods during the Meters migration. Treat provider-version migration and period-boundary semantics as first-class operational evidence, not dependency housekeeping.
- Task 41: Function signatures can hide unproven semantics. `getUsageSummary(..., periodStart, ...)` accepts a period but does not use it when listing/summing provider summaries; the mock test does not catch that. Search for unused correctness parameters and require tests that pin the intended billing period.

## Failed search patterns
- Generic repository-name searches such as “building permits municipal data” produced many datasets/dashboards and little durable ingestion logic. They were materially noisier than code/signature searches.
- Several plausible names surfaced through stale/global code indexing but returned 404 on repository fetch. Treat code-index hits as leads only; require canonical repository fetch before spending deep-inspection budget.
- Generic “government acquisition forecast” / “GovCon forecast platform” searches were similarly noisy and tended to return dashboards, datasets or broad procurement tools without temporal provenance or explicit source-run semantics. Use them for vocabulary only, then pivot to invariant symbols.
- Task 39: Generic `PLC simulator`, `OPC UA simulator` and factory-simulation searches produced many fixed/demo signal servers, educational labs and manually modeled tag trees. They are useful vocabulary sources but poor discovery queries for controller-namespace fidelity. Pivot quickly to engineering-export and addressing signatures such as `L5K`, `L5X`, `Program:`, UDT/AOI, array packing and `AddressSpaceBuilder`/fidelity-test terminology.
- Task 40: Generic `OPC UA client server` searches conflate third-party SDKs, samples and wrappers. For an official pre-FAT oracle, anchor provenance to `OPCFoundation`, then pivot to migration/reconnect/subscription symbols and commit/issue history rather than ranking by popularity.
- Task 41: Generic `usage billing` and Stripe integration searches mostly return one-way meter reporters, SDK wrappers or plan/status reconciliation. They are poor evidence for parity. Pivot to provider read-back and drift signatures such as `listUsageRecordSummaries`, `localTotal`, `stripeTotal`, `reconciliation_diff_pct`, `pushed_total`, adjustment/replay paths and explicit epsilon semantics.

## Useful terminology / signatures
- `permit_versions`, `PermitVersion`, `changed_fields`, immutable snapshot, version-number race, same-batch duplicate permit number.
- `field-completeness audit`, fee-vs-valuation, source-schema metadata audit, field-map regression, non-unique permit identifier, mapping semantic QA.
- Provider-family signatures: Socrata, ArcGIS FeatureServer, Accela/Citizen Access, CKAN, CARTO plus jurisdiction-level mapping configuration.
- Acquisition-forecast signatures: `gsa_gateway`, `dhs_apfs`, `state_forecast`, `ForecastSync`, `first_seen_at`, `last_updated_at`, JSONB `history`, `get_forecast_history`, `_compute_history_changes`, `last_sync_status`, `partial`, `failed`.
- Reliability anti-pattern to search for: parser/fetch layers returning `[]` after structural-response errors while outer orchestration interprets zero errors as success.
- Virtual-commissioning signatures: `L5KParser`, `RockwellLogixPolicy`, `AddressSpaceBuilder`, `Program:<Prog>`, `array-of-UDT`, BOOL `Tag[word].bit`, AOI `EnableIn`/`EnableOut`, `ExternalAccess`, canonical NodeId, fidelity test, cross-format equivalence, real export corpus, fail-loud parse accounting.
- OPC-UA protocol/pre-FAT signatures: `ManagedSession`, `SessionReconnectHandler`, `ConnectionStateMachine`, `TransferSubscriptions`, `RepublishAfterTransfer`, `RecoverTransferredMessagesAsync`, `AuditRegression`, `RecreateInPlaceCoreAsync`, `RunWithPublishingQuiescedAsync`, `TransportConnectedSessionReactivating`, `master378`.
- Usage-parity signatures: `listUsageRecordSummaries`, provider usage summary, `localTotal`, `stripeTotal`, `pushed_total`, epsilon, `reconciliation_diff_pct`, `reconciliation_diff_abs`, watermarks, replay, pending adjustment, approved/reverted adjustment, parity workflow, test clocks.
- Usage-parity anti-patterns: one-way push with no provider read-back; reconciliation that only checks subscription status/plan; unused period/range parameters; parity demos that do not exercise the production route contract; automatic repair that silently declares one side authoritative.

## Candidate search skill — two-task evidence, eligible for promotion later
- SKILL NAME: Invariant-triad code search for ingestion planes
  - WHEN TO USE: A benchmark asks for a heterogeneous ingestion platform where historical correctness, semantic normalization and operational source health matter more than frontend breadth.
  - PROCEDURE: Search separately for (1) connector-family/provider signatures, (2) immutable/version/diff primitives, and (3) domain-semantic or run-health invariants; intersect candidates only after each axis is evidenced in source/tests/schema/history. Then independently trace the diff algorithm and red-team whether a source can false-green an empty/invalid fetch.
  - WHY IT WORKED ON TASK 37: It surfaced the zero-star `adamleap02/PermitBuild`, whose connector + append-only version/diff + semantic mapping-QA combination was much clearer in source/tests than in generic repository-name search.
  - WHY IT WORKED ON TASK 38: It surfaced `davidlarrimore/curatore-v2`, where GSA/DHS/State connector signatures intersected with explicit history/diff code and success/partial/failure orchestration; generic GovCon searches were materially noisier.
  - FAILURE MODES: Field/status names can be decorative; require execution-path verification. Stored snapshots are not enough unless a usable diff/read path exists. Run-state enums can still conceal false-green parser behavior. Identity keys can break continuity even when history arrays are correct.
  - STATUS: supported by two distinct benchmark tasks (37 and 38), therefore eligible for later SEARCH_SKILLS promotion under the benchmark rule. Not promoted in this write to avoid widening benchmark scope and central-file race risk.

## Candidate generalization — five-task evidence, not yet promoted centrally
- SKILL NAME: Executable-invariant intersection search
  - WHEN TO USE: A task asks for a system whose value depends on several independent correctness contracts rather than one headline feature.
  - PROCEDURE: Express the target as three independently searchable implementation invariants; search each axis with code/test/schema/history signatures; intersect candidates; then have the verifier inspect the exact execution path and at least one negative/failure assertion for each axis. Additionally, validate that any advertised end-to-end demo still matches the current route/OS/provider contract.
  - EVIDENCE: Tasks 37 and 38 succeeded with connector/source + temporal evidence + semantic/run-health invariants. Task 39 generalized the same structure outside ingestion: engineering-artifact import + canonical vendor addressing + executable fidelity regression tests surfaced a materially stronger virtual-commissioning target than generic simulator search. Task 40 extended it to protocol stacks: first-party implementation breadth + migration contract + negative reconnect/subscription regression knowledge separated the useful official pre-FAT oracle from generic SDK breadth. Task 41 extended it to financial operations: local meter truth + independent provider read-back + governed parity/repair separated a real reconciliation kernel from one-way billing integrations, while workflow/API inconsistencies prevented overclaiming production proof.
  - FAILURE MODES: The three axes can all exist decoratively in docs. Require source-level intersection in one functioning system; verify negative assertions and known limitations; do not infer production deployment from unit fidelity, certification, first-party status or demo labels alone. Stale demo scripts and unused correctness parameters are high-value red-team targets.
  - STATUS: evidence-backed across five distinct benchmark tasks; retained in pair state only. `SEARCH_SKILLS.md` remains unchanged during the frozen benchmark run.

## Candidate search skill — two-task evidence, eligible for later promotion
- SKILL NAME: Protocol-regression archaeology for pre-FAT systems
  - WHEN TO USE: Industrial/protocol software where commercial value depends on upgrade compatibility, reconnect/recovery behavior or field failure modes rather than only supported features.
  - PROCEDURE: Pin an exact implementation revision; identify the migration/compatibility contract; search commit history for concrete semantic failures; trace each important fix to a regression test; then search issues newer than the pinned head for unresolved contradictions. Convert unresolved paths into explicit adversarial pre-FAT scenarios rather than treating them as reasons to discard the whole stack automatically.
  - WHY IT WORKED ON TASK 39: Parser/release archaeology showed that the L5K grammar had been rewritten after real-file corruption and unsupported L5X was withdrawn instead of being overclaimed, making history itself a fidelity signal.
  - WHY IT WORKED ON TASK 40: OPC-UA client audit history exposed a dense reconnect/subscription defect corpus and current issue #4508 surfaced a destructive-restart deadlock that feature/certification surfaces would not reveal.
  - FAILURE MODES: Issue reports may be unreproduced; commit prose can overstate test coverage; a regression fix may not apply to the pinned branch; certification can be misread as proof of every runtime path; unresolved issues can be over-weighted into rejecting an otherwise valuable oracle.
  - STATUS: supported by two distinct benchmark tasks (39 and 40), therefore eligible for later promotion under the benchmark rule. Retained only in pair state during the frozen benchmark.

## Task 42 evidence-backed lessons
- Task 42: In billing/accounting hunts, `double-entry` labels are weak. The strongest implementation conjunction is construction-time balanced-post rejection + balances derived from postings + a separate unique natural-key dedupe register + retry/duplicate tests + append-only mutation hardening. `cboxdk/laravel-billing` cleared all five while also showing real subscription, invoicing, metering, refund/chargeback and reconciliation depth.
- Task 42: Add a database-boundary bypass pass to money-system verification. Domain-object invariants can be bypassed by raw SQL: at pinned revision `ac3305f...`, balance equality is enforced in `LedgerTransaction`; MySQL/MariaDB block UPDATE/DELETE through triggers, but PostgreSQL/SQLite receive no shipped immutability trigger, and privileged raw INSERT can still bypass the debit=credit constructor. Treat this as a production-hardening requirement rather than evidence that the kernel itself is fake.
- Task 42: Commit history that records a concrete money race is high-value maturity evidence. Commit `2f79e63...` documents a first-reconcile missing-row lock race that could double-count from genesis and fixes it by seeding the checkpoint with `insertOrIgnore` before `FOR UPDATE`; that is stronger evidence than generic `atomic`/`idempotent` prose.
- Task 42: CI executability must be verified separately from test-count claims. HEAD explicitly admits that a prior lockfile gate caused later checks/tests to be skipped for multiple commits; the author's local 413-test report is useful repository evidence but was not independently reproduced in this benchmark.
- Task 42: Generic `subscription billing` and `usage billing` searches surface many real billing products without a governed accounting boundary. Pivot quickly to signatures such as `LedgerTransaction`, `UnbalancedTransaction`, natural `PostingKey`, `billing_ledger_postings`, reversal posting, derived balance, append-only trigger and retry/idempotency tests.
- Task 42: The executable-invariant-intersection method now has evidence across a sixth distinct benchmark task and a sixth domain shape. Money systems add a mandatory fourth verifier axis: try to bypass the domain invariant at the database boundary and distinguish application-level correctness from tamper-resistant persistence. Keep this lesson in pair state only; `SEARCH_SKILLS.md` remains unchanged during the frozen benchmark.

## Task 43 evidence-backed lessons
- Task 43: Evaluator quality requires provenance independence, not merely an `expected` field. A valid golden evaluator should store literal hand-derived economic outputs and decision buckets in a separate artifact and the verifier should trace imports/calls to ensure production rating/audit helpers cannot generate those expected values.
- Task 43: Exact money truth and action truth must both be present. `justicebajaj161/Freight-Audit-Console` has hard-coded action/status expectations but lacks a separate exact-dollar oracle; `indy-viberr/stowaway` has hand-authored planted-rule labels and positive aggregate leakage assertions but no literal per-case money/action truth; `B612XXXX/FreightAuditKit` has expected status counts/labels but not an independent monetary oracle. These are useful tests, but not substitutes for the benchmark invariant.
- Task 43: Planted anomaly manifests, OCR benchmarks, production-engine-generated expected charges, positive-leakage checks and permissive action sets are recurring false-positive patterns for independent-evaluator searches. Treat them as near-misses unless the expected money/action answers are authored independently from the engine under test.
- Task 43: A calibrated `NO_FIND` is evidence-backed progress when the exact evaluator invariant is absent after broad source/test/fixture/history inspection. Do not weaken the target to promote an attractive freight-audit engine.
- Task 43: Product opportunity exposed by the absence: an independent Freight Audit Golden Regression Certification pack can be built around a small corpus of contracts/rate confirmations, shipment facts and invoices with hand-calculated payable/recoverable dollars plus one action bucket per case. Its commercial value is independent evidence that engine/rule/AI changes preserve financial decisions.
- Task 43: Useful evaluator-search signatures are `golden_cases`, `answer_key`, `oracle`, `expected_dollars`, `expected_recovery`, `expected_action`, `action_bucket`, literal cents/dollars, and a separate evaluator/grader module. Search these independently from freight-engine vocabulary, then intersect only after provenance review.
- Task 43: The executable-invariant-intersection method now also demonstrates a negative-case benefit: it prevented false promotion when domain functionality and partial truth fixtures existed but the third invariant—independent money/action oracle provenance—did not. `SEARCH_SKILLS.md` remains unchanged during the frozen benchmark.
