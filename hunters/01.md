# Hunter 01 — Abandoned SaaS & forgotten products

## Mission
Search public GitHub broadly for obscure, undernoticed, rare, unusually valuable, and monetizable public software, datasets, algorithms, workflows, schemas, standards, research code, or technical/business infrastructure relevant to **Abandoned SaaS & forgotten products**.

## Catalog rule
Record every meaningful candidate inspected in this file. For strong candidates, include detailed evidence. For weak/rejected candidates, record a concise reason so future runs do not repeat the work.

## Rights and safety
- Publicly visible is not automatically public domain.
- Respect repository/data licenses and copyright.
- No-license code is inspect/learn/clean-room only unless permission is established.
- Do not collect, reproduce, preserve, or exploit credentials, private/personal data, authentication material, accidentally exposed confidential information, or leaked trade secrets.
- Do not exploit vulnerabilities or unauthorized access paths.

### shawndibble/self-storage
- URL: https://github.com/shawndibble/self-storage
- Exact commit / revision: `f356e9baf1eac679ea6014d4b72958756ed434ee`
- Date inspected: 2026-09-19
- Status: **watch — archived but real vertical product**
- What it contains: Archived Laravel/Inertia/React self-storage management application with authentication, storage-unit/size management, users, invoices and payments, Docker/Laravel Sail setup, seeded demo data, CI/deploy workflows and a former hosted site.
- Rare or undernoticed value: Four stars and archived status despite a real operational vertical codebase. The source tree confirms domain controllers for storage units, sizes, invoices and payments rather than a landing-page prototype.
- Monetization path: GPL-compliant hosted/self-hosted product or clean-room requirements reference for independent self-storage operators. Higher-value expansion would need delinquency/autopay/access-control and portfolio reporting rather than merely reselling the existing CRUD app.
- Likely buyer / user: Small independent self-storage operators and local multi-site owners underserved by larger storage-management suites.
- Build-time or data advantage: Could save 1–3 months of basic self-storage CRUD/billing/auth scaffolding, but its age and narrower feature set limit the shortcut.
- Concrete evidence inspected: Repository metadata showing archived status, GPL-3.0 and low attention; exact latest commit; README/Docker setup; recursive tree showing `StorageUnitController`, `SizeController`, `InvoiceController`, `PaymentController`, auth, CI and deployment files.
- License / rights: **GPL-3.0**.
- Reuse classification: **Copyleft**; commercial use is possible with GPL obligations, but it is not a clean proprietary SaaS foundation.
- Why it is not already obvious / crowded: Archived, four-star personal project with minimal README copy; meaningful billing/unit functionality is visible mainly in the tree.
- Combination opportunities: Could inform a modern storage vertical built on a permissive SaaS chassis; pair conceptually with access-control/gate integrations and delinquency/payment-recovery tooling.
- Next action: Deprioritize unless a specific self-storage buyer wedge appears. If revisited, inspect lease/delinquency/autopay semantics before deciding whether GPL deployment is worthwhile.

### Jinotaer/Multi-Tenant-Laundry-Shop-Management-System
- URL: https://github.com/Jinotaer/Multi-Tenant-Laundry-Shop-Management-System
- Exact commit / revision: `cc0f11d322e7e5a80628001cec3255a68914f2fd`
- Date inspected: 2026-09-19
- Status: **rejected for direct reuse; watch as vertical SaaS reference**
- What it contains: Zero-star Laravel 12 multi-tenant laundry SaaS with isolated tenant databases/subdomain routing, owner/manager/staff/customer roles, customer profiles and loyalty, order/status workflows, services/pricing, PayMongo payments, invoicing, shop subscription plans/trials, expenses/revenue analytics, branding and email notifications.
- Rare or undernoticed value: A surprisingly complete SaaS operating model for a mundane niche, including both end-customer laundry operations and platform-level tenant subscriptions. It demonstrates how much vertical workflow can hide in a zero-star repo.
- Monetization path: Do **not** reuse the application source. Clean-room product/requirements reference only unless the rights-holder grants a commercial license. The niche itself could support a modern route/pickup/delivery or B2B linen-service product, but standalone laundromat SaaS likely has lower ACV than current top hunts.
- Likely buyer / user: Laundry shops, wash-and-fold operators and potentially pickup/delivery laundry services.
- Build-time or data advantage: Requirements discovery value only; the code would otherwise represent several months of multi-tenancy/order/payment/subscription work, but those rights are not granted.
- Concrete evidence inspected: Repository metadata (0 stars, no GitHub-recognized license), exact latest commit adding tenant resources/migration, and README detailing tenant isolation, roles, orders, payments, invoices, subscriptions, analytics, tests and deployment.
- License / rights: README explicitly states **“Proprietary Software. All rights reserved.”** The later note that Laravel itself is MIT applies to the framework, not this application.
- Reuse classification: **Inspect/learn/clean-room only; copyrighted proprietary application source**.
- Why it is not already obvious / crowded: Zero stars and a student/project-style repository name despite product-shaped SaaS breadth.
- Combination opportunities: Clean-room vertical requirement ideas could be applied to a permissive generic CRM/order chassis; do not combine source.
- Next action: No further source archaeology unless licensing changes or a high-value commercial-linen/B2B route angle emerges.
