# Hunter 02 — Enterprise B2B workflows

## Mission
Search public GitHub broadly for obscure, undernoticed, rare, unusually valuable, and monetizable public software, datasets, algorithms, workflows, schemas, standards, research code, or technical/business infrastructure relevant to **Enterprise B2B workflows**.

## Catalog rule
Record every meaningful candidate inspected in this file. For strong candidates, include detailed evidence. For weak/rejected candidates, record a concise reason so future runs do not repeat the work.

## Rights and safety
- Publicly visible is not automatically public domain.
- Respect repository/data licenses and copyright.
- No-license code is inspect/learn/clean-room only unless permission is established.
- Do not collect, reproduce, preserve, or exploit credentials, private/personal data, authentication material, accidentally exposed confidential information, or leaked trade secrets.
- Do not exploit vulnerabilities or unauthorized access paths.

### proforcetech/phparm
- URL: https://github.com/proforcetech/phparm
- Exact commit / revision: `a691ebfdea93a20f9de5f8a076430c859f299255`
- Date inspected: 2026-09-19
- Status: **strong**
- What it contains: A zero-star PHP line-of-business platform whose shipped core spans customers, estimates, work orders, invoices, time/dispatch and broader WOMS modules. The repository also contains an implemented recurring-service route subsystem with `service_routes`, `route_stops`, `route_visits`, visit photos, QR-gated field execution, state transitions and audit writes. Its vertical design corpus covers building/property repair, equipment service, fleet, IT support, physical security and commercial cleaning/janitorial.
- Rare or undernoticed value: The strongest hidden capability is recurring contract service verification. The janitorial model links recurring routes/stops/visits to service contracts and contract-entitlement consumption, while the source has concrete photo-verification and visit-consistency machinery rather than only README claims. This is unusually close to a commercial-cleaning/facility-services proof-of-service product.
- Monetization path: Verticalize as a managed commercial cleaning/facility-service operations product: contract routes, QR arrival, required photo proof, exception handling, service-entitlement consumption and invoice support. Charge per site/crew plus onboarding/migration; a higher-value variant can quantify missed visits, noncompliance and billable out-of-scope work.
- Likely buyer / user: Regional janitorial contractors, building-service contractors and multi-site facility-service operators that lose margin through missed visits, disputed service, weak field proof or contract leakage.
- Build-time or data advantage: Potentially 4–9 months of route/field-proof/work-order/audit plumbing for a focused vertical, with more generic back-office functionality already present.
- Concrete evidence inspected: Repository metadata and root MIT license; exact latest commit; recursive tree showing Docker/CI/mobile surfaces; `docs/woms-service-lines.md`; `docs/features.md`; implemented `src/Services/ServiceRoutes/RouteVisitPhotoRepository.php`, `PhotoVerifier.php`, `RouteVisitService.php`; and `database/migrations/165_recurring_service_routes.sql`. `RouteVisitService` explicitly centralizes state transitions, completion-photo guard, QR validation, audit writes and transaction consistency. Some broader service-line material remains design/expansion documentation, so only implemented modules are treated as shipped.
- License / rights: **MIT**, verified by repository metadata/root LICENSE.
- Reuse classification: **Commercially reusable / permissive**, subject to MIT notice obligations.
- Why it is not already obvious / crowded: Generic `phparm` name, no repository description and zero stars hide a much larger vertical workflow system; the recurring-service assurance value appears mainly in source files and internal docs.
- Combination opportunities: Pair with `XetaSuite/Core` for facility asset/inventory depth, `warrengalyen/OpenFleet` for stronger maintenance policy/testing, and invoice/reconciliation components for measurable contract leakage recovery.
- Next action: Inspect the actual contract-consumption ledger, invoice linkage, tenant/auth boundaries and tests around route completion; prove one end-to-end synthetic cleaning contract from scheduled route through proof-of-service to invoice/exception.
