## BEST NEW FIND
**Name:** Freight settlement tenant/business-unit isolation defect and fix

The persistent settlement reference added in Run 10 correctly protected money capacity, replay, reversal and concurrency, but it did not carry `buyer_id` or `business_unit` at the persistence layer. `RecoveryClaim`, `SettlementEventRecord`, `CounterEventRecord`, settlement tables and all lookup/allocation queries were globally keyed. That meant proof-layer scope checks could be correct while a shared settlement database still had a cross-customer matching/read boundary defect if local identifiers overlapped.

This run fixed that defect by binding every `SettlementStore` instance to one buyer/business-unit scope and including that scope in every persisted identity, query, residual calculation, allocation, reversal, uniqueness rule, foreign key, trigger and count. Scope is selected at repository construction rather than being caller-selectable on each money row.

## Changes
- `freight/settlement_schema.sql`
  - adds `buyer_id` and `business_unit` to recovery claims, review locks, settlement events, allocation edges, counter-events and reversal edges;
  - replaces global local IDs with composite `(buyer_id, business_unit, local_id)` primary/unique/FK identities;
  - scopes source-hash uniqueness by buyer/business unit;
  - scopes capacity, currency, review-lock and reversal triggers.
- `freight/settlement_store.py`
  - binds the store to `buyer_id` + `business_unit`;
  - scopes all reads, writes, matching, residuals, realized recovery and fee-eligible recovery;
  - fails closed if an existing database exposes the legacy unscoped `recovery_claims` schema rather than silently operating against it.
- `freight/test_settlement_store.py`
  - preserves the prior 21 settlement/concurrency tests;
  - adds five cross-scope negative tests.

## Claims tested
Local validation passed **26/26 tests**.

New isolation regressions prove:
1. two buyers may safely reuse the same local claim/event identifiers and source hashes in one database;
2. a settlement event in Buyer B cannot auto-match a claim in Buyer A;
3. scoped read/count/residual methods cannot observe another buyer's records;
4. direct SQL cannot create a cross-scope allocation edge because composite foreign keys fail closed;
5. a legacy unscoped settlement schema is rejected rather than silently treated as production-safe.

The prior money/concurrency invariants still pass: duplicate replay is idempotent, one event cannot be consumed twice, concurrent settlement events cannot overconsume a claim, concurrent reviewed edges cannot overconsume an event, duplicate returns reverse once, reversals reopen only claim capacity, and ambiguous partial returns remain REVIEW.

## COMBINATIONS DISCOVERED
The proof chain is now stronger at the persistence seam:

`authenticated buyer/BU scope -> controlling authority -> deterministic expected charge -> unique recovery claim -> issued adjustment -> independent settlement event -> scope-bound one-use allocation edge -> linked counter-event -> net realized recovery`.

The key new insight is that proof objects carrying tenant scope are insufficient unless the *money-bearing persistence transition itself* uses scope as part of identity and referential integrity.

## EMERGING TECHNOLOGY SIGNALS
Strengthens `RAD-001 Proof-carrying operational software` and `RAD-006 Authority-aware money assurance`. A trustworthy financial proof is increasingly a tuple of **authority + tenant scope + immutable external observation + one-use amount edge + reversible counter-event**, not merely a correctly scoped report object.

## FAILURES / NEGATIVE KNOWLEDGE
- Tenant/business-unit scope only at the proof/report layer is not enough.
- Globally unique local settlement IDs are not a substitute for tenant-qualified identity.
- Application-layer filtering without composite database referential integrity can still permit hostile/direct cross-scope writes.
- Reusing an old unscoped database after adding scoped code is unsafe; migration must be explicit and fail closed.
- Generic freight repository hunting remains lower value than closing the authorized external buyer outcome.

## CROSS-AGENT REFERRAL
