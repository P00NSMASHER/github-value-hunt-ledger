## Acceptance-path inspection
The run inspected the currently trusted pre-parser transition in `freight/input_guard.py` after the prior CSV hardening and found three remaining fail-closed/resource-boundary seams:

1. **Cross-platform filename semantics:** `_safe_leaf_filename` used host `pathlib.Path` only. On the Linux CI/runtime, Windows traversal/drive/UNC forms such as `..\\invoice.csv`, `C:\\temp\\invoice.csv`, and `\\\\server\\share\\invoice.csv` are not interpreted as path traversal in the same way they would be on Windows. A colon-bearing ADS-like name was likewise not explicitly blocked.
2. **XML shape was not bounded:** XML input was screened for DTD/entity text, NUL and long physical lines, but was not required to be well formed and had no explicit nesting-depth, element-count or per-element-attribute budget. A malformed or deeply structured XML could therefore pass the pre-parser boundary even though `FRT-SEC-002` explicitly requires hostile-input depth/resource controls.
3. **EDI segment validation materialized split lists:** the EDI/X12 segment-length guard constructed `text.split(...)` lists and then a `chunks` list. Under a byte-allowed file with many delimiters this created avoidable object/memory amplification before the real parser sandbox exists.

## Implementation
Final exact code revision: `7f8bf80fd2baa63153bf4ece236fa7eaa93d42a4`.

Changes:
- filename validation now checks POSIX and Windows path semantics, rejects both slash styles, drive/root forms, control characters and colon-bearing ADS/drive-style names;
- `IngestPolicy` now has explicit positive `max_xml_depth`, `max_xml_elements`, and `max_xml_attributes_per_element` budgets;
- XML shape validation uses event callbacks from Expat rather than building an ElementTree, so the preflight counts depth/elements/attributes without retaining an XML tree;
- malformed XML becomes a stable typed `xml_parse_error`;
- XML that crosses the explicit budgets becomes `xml_depth_limit_exceeded`, `xml_element_limit_exceeded`, or `xml_attribute_limit_exceeded`;
- EDI/X12 segment-length checking is now a single-pass counter with constant auxiliary space instead of delimiter `split()` list materialization.

Test revision `3c5c7e107827ee3b17941378a712cf437ba9becc` added hostile cases for malformed XML, depth, element count, attribute count, Windows traversal/drive/UNC/ADS-style filenames, many short EDI segments, and positive-policy validation. The isolated input-guard suite passed 32/32 locally after the final Expat implementation.

## Claims / limits

## Negative knowledge
- DTD/entity rejection alone is not a bounded XML ingestion policy.
- Host-native `pathlib.Path` is insufficient when uploaded filenames can later cross OS/storage boundaries.
- A raw byte limit does not prevent parser/pre-parser memory amplification caused by token/list materialization.
- A typed pre-parser rejection is stronger operational evidence than an unhandled parser crash, but it is not a sandbox receipt.
