### matthewmakh/NYC-DOB-permit-search-and-parse
- URL: https://github.com/matthewmakh/NYC-DOB-permit-search-and-parse
- Exact commit / revision: `85dc61aa48f810282de53e61c399b00f19c2a40a`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: A functioning NYC construction/property intelligence pipeline and deployed-product backend. The safe public-record portion ingests DOB permit data, derives/links BBL building identifiers, enriches buildings from municipal property/assessment/transaction sources, geocodes records, stores them in PostgreSQL, runs scheduled enrichment and serves an interactive dashboard. Recent source also contains working subscription/payment plumbing, indicating this is more than a scraper demo.
- Rare or undernoticed value: The valuable piece for PermitPlate is the entity-linking spine across permit → BBL/building → public property attributes → transaction history → map coordinates. `step1_link_permits_to_buildings.py` implements borough/block/lot normalization and building linkage rather than leaving records as disconnected permit rows.
- Monetization path: Permit-to-sales-opportunity intelligence, project/property change alerts, contractor territory dashboards, early-stage construction lead feeds and public-record enrichment APIs. Use only lawfully available/public business/project information; do not build around personal-contact harvesting.
- Likely buyer / user: Specialty contractors, building-product suppliers, service companies, construction sales teams, property investors and local market-intelligence teams.
- Build-time or data advantage: High as a clean-room reference for NYC permit/property entity resolution and scheduled enrichment. It demonstrates how to turn DOB records into stable property entities instead of a raw permit feed.
- Concrete evidence inspected: `README.md` pipeline architecture; exact latest commit; `step1_link_permits_to_buildings.py` BBL derivation/building-link logic; recent dashboard/payment code visible in the latest commit. The repository also contains contact/enrichment features; those personal/contact-oriented components were deliberately not harvested or preserved for this hunt.
- License / rights: No repository `LICENSE` was found at the inspected revision. Public source datasets have their own terms and should be verified independently; public availability does not transfer rights in repository code.
- Reuse classification: Inspect/learn/clean-room only unless permission or a clear license is established. Reimplement public-record connectors from source APIs under their own terms.
- Why it is not already obvious / crowded: Search results look like “another DOB scraper,” but inspection shows an actual property-entity model, enrichment pipeline, deployment/dashboard and monetization plumbing.
- Combination opportunities: PermitPlate can clean-room the permit→property normalization pattern, then combine it with existing entity-resolution/OCR/rules findings to score trade-specific opportunities without copying the unlicensed implementation.
- Next action: Independently implement and test a NYC BBL/property canonicalization adapter directly against official public APIs/data, then benchmark whether it improves PermitPlate duplicate suppression and account-level lead grouping.
