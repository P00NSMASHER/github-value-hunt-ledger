### rocket-creative/SYDRA
- URL: https://github.com/rocket-creative/SYDRA
- Exact commit / revision: `24d8dd93b3065f1043ea1b496a3906c3b6afecf2`
- Date inspected: 2026-09-19
- Status: watch
- What it contains: A zero-star healthcare administrative/pricing application with a concrete Transparency in Coverage data pipeline. The inspected `data-pipeline/scripts/03_parse_mrf.mjs` streams payer in-network MRF JSON/JSON.GZ rather than loading the whole file, filters to a configured billing-code set, extracts accepted negotiated-price types, caps samples for memory control, computes median/min/max rates and upserts payer/code benchmark rows.
- Rare or undernoticed value: The useful piece is a compact, working pattern for targeted extraction from enormous public payer rate files, plus a candid limitation: the current output is national because raw TiC rates are attached to provider groups rather than states, and meaningful geographic benchmarking requires NPI/provider-reference enrichment. Zero stars and a consumer-facing product shell hide the data-engineering value.
- Monetization path: Independently rebuild the pattern from CMS schemas and public payer files as a rate-benchmarking/contracting intelligence service for billing companies, provider finance teams, self-funded employer advisers or IDR support. The commercial product should retain provider/network/geography/service context rather than relying on a single undifferentiated national median.
- Likely buyer / user: Medical billing companies, provider contracting/revenue-integrity teams, benefits consultants, self-funded employer advisers and healthcare price-transparency analysts.
- Painful problem: Public payer MRFs are too large and structurally awkward for ordinary analytics workflows, so organizations often cannot turn legally public negotiated-rate data into practical comparisons without a specialized ingestion layer.
- Build-time or data advantage: Clean-room learning value of several weeks to a few months for targeted streaming, normalized code filtering and benchmark persistence; the repository itself is not directly reusable because no license was detected.
- Concrete evidence inspected: Public repository metadata (0 stars/0 forks, TypeScript); exact HEAD commit; `data-pipeline/scripts/03_parse_mrf.mjs`; code search for MRF-related tests found no dedicated test result for the inspected parser path.
- License / rights: No repository license detected at the inspected revision. Public CMS/payer data and schemas have their own terms and provenance requirements.
- Reuse classification: Inspect / learn / clean-room implementation only unless permission is established.
- Why it is not already obvious / crowded: The repository name gives no healthcare clue, it has zero stars, and the high-value MRF parser is buried under `data-pipeline/scripts/` rather than presented as a standalone library.
- Combination opportunities: Reimplement against authoritative CMS TiC schema/data, join provider references to NPPES for geography and provider identity, and pair with a deterministic evidence layer so every benchmark can cite payer/file/effective-date/provider-group provenance.
- Next action: Build a rights-clean miniature benchmark from an official CMS schema plus one public payer MRF and NPPES enrichment; compare provider/geography-aware percentiles against the simplistic national-median baseline.
