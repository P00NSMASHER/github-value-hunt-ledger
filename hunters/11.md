- Status: strong (rights-constrained)

Sell project-screening reports/API access to developers, brokers, investors and infrastructure advisers.
- Likely buyer / user: Renewable developers, BESS developers, project-finance teams, infrastructure investors, land/interconnection advisers, power-market consultants.
- Build-time or data advantage: The committed normalized grid/layer structure and methodology could save roughly 2–5 months of data-model and spatial-screening design work even if reimplemented clean-room. The committed derived data are potentially more valuable than the code, subject to verifying source-data redistribution rights.
- Concrete evidence inspected: Repository metadata; exact commit; recursive tree showing benchmark grids, ISO/RTO annual LMP Parquets, resource/revenue layers, maps and methodology docs; README architecture/methodology; `scripts/01_build_price_layer.py`. Important limitation: that script explicitly says the actual build was done interactively and requires a separate ReWEP extraction pipeline plus a calibrated price model, so the repository is not fully reproducible from the visible scripts alone.

- Reuse classification: Inspect/learn/clean-room only unless permission and dataset rights are established.
- Why it is not already obvious / crowded: 0 stars / 0 forks at inspection despite a fairly substantial committed national screening dataset and an explicit resource × price revenue framework.
- Combination opportunities: Strong clean-room combination with licensed `GridSphere-Tools/Arbiter` for live/normalized ISO data and `KingArthur289/fluxpeak` for storage/flexibility economics; could become a site-screening front end that hands high-value regions into deeper dispatch/revenue simulations.
- Next action: Independently reconstruct a small 50–100-cell benchmark from lawful upstream sources and compare rankings; verify rights for each upstream data source before considering any committed Parquet reuse.
