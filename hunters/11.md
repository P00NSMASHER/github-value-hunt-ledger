# Hunter 11 — Energy, utilities & grid operations

## Mission
Search public GitHub broadly for obscure, undernoticed, rare, unusually valuable, and monetizable public software, datasets, algorithms, workflows, schemas, standards, research code, or technical/business infrastructure relevant to **Energy, utilities & grid operations**.

## Catalog rule
Record every meaningful candidate inspected in this file. For strong candidates, include detailed evidence. For weak/rejected candidates, record a concise reason so future runs do not repeat the work.

## Rights and safety
- Publicly visible is not automatically public domain.
- Respect repository/data licenses and copyright.
- No-license code is inspect/learn/clean-room only unless permission is established.
- Do not collect, reproduce, preserve, or exploit credentials, private/personal data, authentication material, accidentally exposed confidential information, or leaked trade secrets.
- Do not exploit vulnerabilities or unauthorized access paths.

### TextureHQ/commongrid
- URL: https://github.com/TextureHQ/commongrid
- Exact commit / revision: `7f8393b8437a7b459678707f0592efa286c81b69`
- Date inspected: 2026-09-19
- Status: strong (database rights are clear; application/source-code rights require separation)
- What it contains: A one-star, actively maintained U.S. electric-grid reference database and explorer. The inspected revision ships 3,132 utility entities, ISO/RTO and balancing-authority registries, roughly 3,000 utility/ISO/BA/CCA regions and GeoJSON territories, plus roughly 4,065 wholesale pricing nodes. Utility records expose EIA identity, segment, customer/revenue/sales/peak-demand/meter attributes and organizational/grid relationships. The repository also contains sync scripts for EIA power plants, substations, transmission lines, EV charging and pricing nodes, with scheduled-sync tests and an operational Postgres/Next.js application.
- Rare or undernoticed value: The difficult part is not a map UI; it is the normalized identity + geography layer connecting thousands of utilities to EIA IDs, service territories, ISO/RTO/BA relationships and pricing-node context. That is a valuable join spine for DER sales, site diligence, utility prospecting and grid intelligence.
- Monetization path: Build a utility-territory/site-intelligence API or high-ticket developer/DER screening product: given a coordinate/property/project, resolve likely serving utility/territory, grid region and public utility facts, then layer interconnection queues, rates, DER hosting capacity, outages or project economics. Another path is enterprise utility-account/entity master data for energy SaaS vendors.
- Likely buyer / user: DER/solar/storage developers, data-center and industrial site-selection teams, EV infrastructure developers, energy SaaS vendors, grid consultants, utility-facing sales teams, infrastructure investors.
- Build-time or data advantage: Roughly 3–8 months of entity normalization, boundary acquisition/cleaning, relationship modeling and data-pipeline work for a U.S.-focused grid-intelligence MVP, before adding the higher-value decision layers.
- Concrete evidence inspected: Repository metadata and exact latest commit; README schemas/counts; `docs/DATA_CATALOG.md` source/provenance inventory; `package.json` sync commands for plants, transmission lines, EV charging, pricing nodes and substations; `scripts/__tests__/sync-workflows.test.ts`; latest commit fixing least-privilege privileges for the live daily sync role. The Data Catalog distinguishes currently available data from planned/in-progress sources; only shipped/currently evidenced layers are treated here as present.
- License / rights: Root `LICENSE` grants the **database and its contents** under ODbL 1.0, with attribution/share-alike requirements for public adapted databases, and identifies DbCL for individual contents. GitHub reports `NOASSERTION/Other`. The inspected license is database-focused and does not clearly grant a separate permissive software-code license for the application/sync source. Upstream ISO/ArcGIS/source terms also remain source-specific.
- Reuse classification: Database/data reusable subject to ODbL/DbCL and upstream terms; conservatively treat repository application/sync source as inspect/learn/clean-room unless a separate software license grant is established.
- Why it is not already obvious / crowded: Only one GitHub star at inspection despite an actively synced national utility identity/geography dataset and production application.
- Combination opportunities: Excellent lawful data spine for clean-room `D-ivy/renewables_indexes` methodology, the MIT `deployment-gap-model` interconnection ETL, live ISO adapters and renewable/BESS siting tools. The strongest combination is coordinate → utility/territory → queue/project context → market/resource economics.
- Next action: Verify ODbL obligations for the intended product architecture, then benchmark coordinate-to-utility resolution in 100 known sites and join the result to an independently sourced interconnection-queue sample.
