### serhmarch/modbusua
- URL: https://github.com/serhmarch/modbusua
- Exact commit / revision: `455be0eedd5145ac2bd8a05d920cf075b2ebaab7`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: Cross-platform C++ Modbus-to-OPC-UA gateway using open62541/libmodbus with a JSON-driven device/model mapping layer and bidirectional variable access.
- Rare or undernoticed value: Brownfield industrial protocol translation is integration-heavy and normally buried inside commercial gateways; this repository has only ~11 stars despite implementing the core bridge.
- Monetization path: Managed industrial edge gateway, Modbus estate modernization service, OEM protocol-translation appliance, or a device-modeling/onboarding layer sold to factories and system integrators.
- Likely buyer / user: Industrial system integrators, machine builders, factory OT teams, IIoT vendors, SCADA/MES vendors needing OPC UA exposure for legacy Modbus assets.
- Build-time or data advantage: Saves several weeks to months of protocol plumbing, OPC UA node construction, data-type mapping, and write-back behavior before product hardening/security work.
- Concrete evidence inspected: Repository metadata/license; exact latest revision; `src/ua/device/CnUaDevice.cpp`, where `addObject()`/`addVariable()` create OPC-UA nodes, physical variable types are mapped to UA types, read/write access is set, `updateVariable()` writes source changes into UA, and the UA data-source callbacks proxy reads/writes back to the underlying device. Source tree also contains UA variable/data-type abstractions and sample/resources directories.
- License / rights: MIT according to current GitHub license metadata at the inspected revision; preserve license/copyright notices.
- Reuse classification: permissive reusable code, subject to MIT terms and dependency licenses.
- Why it is not already obvious / crowded: Very small attention footprint and narrowly technical positioning; the economic value is in replacing proprietary industrial protocol gateways/integration labor rather than developer popularity.
- Combination opportunities: Pair with the existing industrial camera/SCADA findings in this lane for a unified brownfield edge collector; pair with network inventory/validation findings in Hunter 35 for OT asset inventory plus protocol normalization.
- Next action: Validate JSON model format against 2-3 real Modbus device maps and estimate effort for TLS/certificate management, store-and-forward telemetry, and remote fleet management.
