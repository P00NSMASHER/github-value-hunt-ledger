### Critical red-team result — source disagreement can still false-merge
The current matcher treats strong identifiers only as positive matches; a contradictory strong identifier is not a negative/veto signal. A canonical asset with `instance_id=A` and an incoming record with `instance_id=B` can still auto-merge if hostname and public IP agree:

- exact normalized hostname score = `0.85 × 0.60 = 0.51`
- public-IP overlap score = `0.75 × 0.40 = 0.30`
- combined = **0.81**, above the default `0.70` merge threshold
- `_match_hard_ids()` merely fails to return a positive hard-ID match when IDs differ; it does not emit `IDENTITY_CONFLICT`.
- `RecordMerger` then logs the differing `instance_id` as field drift/conflict and authority-resolves the value, while still appending the incoming source record to the same canonical identity.

This is unacceptable for the Recovery Census authority plane. A conflict between two concurrently fresh, source-authoritative stable identifiers must be a **hard non-merge assurance state** (`IDENTITY_CONFLICT`) until explicitly adjudicated. Weighted hostname/IP evidence may support a candidate relationship but may not overrule contradictory stable IDs.

## Independent architecture signal — ibencaralg/assetly + 2026 paper
- Repository: https://github.com/ibencaralg/assetly
- Exact revision: `6715ade32d522dce6128daf040125810c68307b9`
- Public license: MIT.
- Status: **research signal / partial implementation, 23/30.**
- The 2026 paper “An Evidence-Based Architecture for Trustworthy Asset Discovery in Cybersecurity-Critical IT Environments” explicitly separates immutable time-scoped observations, persistent asset identity, and derived inventory representation; it argues that identity resolution should be deterministic, auditable and reversible and that observations should not be destructively rewritten when correlation logic changes.
- Code red-team: the current Assetly processor is materially simpler than that architecture. It looks up assets by MAC and then IP and returns the first API result; it can mutate an interface MAC after an IP-only match. Thus the paper is stronger as a design specification than the current repository is as a finished identity-resolution engine.
- Value: supports the Recovery Census design rule that **raw observations are evidence; canonical identity is a revisable interpretation**. Do not overwrite the observation layer when a correlation decision changes.
