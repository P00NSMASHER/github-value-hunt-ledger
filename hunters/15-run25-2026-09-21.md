- the runner-provided Docker/kubectl/tool environment is not pinned in the repository manifest.

GitHub's official secure-use guidance says a full commit SHA is the only immutable way to consume an action and warns that tags can move. Docker's official build guidance states that tags are mutable and a digest is required to guarantee the same image. These independent authorities confirm that an exact repository Git closure cannot by itself establish exact runtime behavior.

## Two-layer RQR contract

A transferable Recovery Qualification Receipt needs both:

1. **Source closure**
   - repository + exact commit provenance;
   - derived digest of exact behavior-bearing Git objects;
   - deterministic canonicalization rule and manifest schema version.

2. **Resolved execution closure**
   - runner image/release identity and SBOM/digest where available;
   - full commit SHAs for every external GitHub Action actually executed;
   - Go toolchain and relevant runtime/tool versions;
   - resolved container image manifest digests, not tags;
   - verified SHA-256 for downloaded Velero/tool archives;
   - kind/Kubernetes/Docker/kubectl/Helm identities;
   - effective E2E command and environment inputs;
   - receipt of the resolutions observed by the runner before subject execution.

Transfer is allowed only when the current source closure equals the qualified source closure **and** the current resolved execution closure equals the qualified execution closure, or when a narrower explicit policy marks a difference as neutral and that neutrality is covered by a planted regression case. Any unresolved reference remains `NO_CURRENT_QUALIFICATION`.

## Capability / experiment impact

- **CAP-010 strengthened:** qualification lineage must be two-layer; repository behavior identity and resolved execution identity are distinct claims.
- **EXP-004 added negative control:** `exact_source_unresolved_runtime`.
- Recommended additional negatives: `action_tag_moved`, `runner_image_changed`, `container_tag_moved`, `download_checksum_missing_or_mismatch`, and `toolchain_changed`.
- Exact commit provenance remains useful but cannot substitute for either layer.
- The current FireDrill subject remains `NO_CURRENT_QUALIFICATION` until a real E2E emits both closure layers and the resulting evidence bytes pass the existing CAP-007 admission matrix.

## Strongest objection / limit

A fully resolved runtime closure can become expensive and over-sensitive. GitHub-hosted runner images and transitive platform services may not expose one perfect immutable identity, and strict equality can force reruns after harmless patch changes. That is a cost/availability problem, not authority to fail open. Start fail-closed, record exact observed resolutions, and add neutral-drift transfer rules only after explicit negative/neutral regression coverage.
