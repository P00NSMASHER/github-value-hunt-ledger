## Concrete finding

A safe RQR cannot be defined as a repository-path allowlist. It needs three independently checked layers:

1. **Source closure** — exact subject commit plus a digest of the actual transitive build/test inputs: evaluated workflow, effective test command, compiled source dependency graph, module graph, embedded assets, fixture/setup scripts and inline manifests.
2. **Resolved execution closure** — exact identities observed during the qualifying run: full action commit SHAs, runner image identity, toolchain versions, downloaded artifact hashes, container image manifest digests, and a digest of behavior-affecting environment/feature inputs.
3. **Capture authority and completeness** — the identity/digest of the mechanism that produced the closure, plus explicit unresolved-input reporting. A manifest produced by an unknown or changed recorder, or one containing any unresolved dependency, is non-transferable even when its remaining digests match.

This third layer is the new delta. A signed manifest can be internally consistent yet incomplete. Closure completeness therefore cannot be inferred from the presence of a digest; it is an evidence obligation tied to a qualified recorder/builder identity.

The proposed fail-closed states are:

- `QUALIFIED`
- `CAPTURE_AUTHORITY_MISMATCH`
- `CLOSURE_INCOMPLETE`
- `INVALID_CLOSURE_DIGEST`
- `SOURCE_CLOSURE_MISMATCH`
- `RUNTIME_CLOSURE_MISMATCH`

## Why FireDrill needs all three layers

The current E2E workflow uses `ubuntu-latest`, `actions/checkout@v7`, `actions/setup-go@v7`, and `helm/kind-action@v1`. It downloads and extracts the Velero CLI with `curl | tar` but does not compare an expected checksum. Its setup script resolves `minio/minio:latest`, `minio/mc`, `velero/velero-plugin-for-aws:v1.10.0`, and `nginx:1.27-alpine` by tag. The E2E fixtures also request tagged Postgres and MySQL images.

A source-only digest cannot say which bytes those tags, runner label, action tags, or download produced during a historical run. Conversely, a runtime inventory without the exact source/test closure misses behavior embedded through Go `//go:embed` assets, the effective `make e2e` command, fixtures, and setup manifests.

GitHub's current secure-use reference states that a full-length action commit SHA is the only immutable action reference. Docker documents that image tags are mutable and digest pinning is what identifies the same image. The SLSA provenance model supplies the right envelope—external parameters, resolved dependencies, builder identity and run details—but says resolved-dependency completeness is best effort, so RQR must make unresolved inputs an explicit non-qualification state rather than treating an ordinary provenance statement as proof of completeness.

## Capability and experiment impact

CAP-010 Recovery Qualification Receipt should model closure capture as a trusted, versioned producer rather than accept a self-declared closure digest. EXP-004 gains permanent negative controls for `unknown_closure_recorder`, `unresolved_dependency_present`, `embedded_asset_changed`, `effective_test_command_changed`, and `closure_digest_not_recomputed`.

A compact interoperable shape can reuse SLSA provenance fields:

- `buildDefinition.externalParameters`: exact subject, workflow and invocation inputs;
- `buildDefinition.resolvedDependencies`: source/module/action/download/image artifacts with digests;
- `runDetails.builder.id` and `builderDependencies`: recorder/executor trust identity;
- `runDetails.byproducts`: evaluated workflow, closure manifest and semantic E2E result.

RQR still needs stricter policy on top: any behavior-bearing input that remains unresolved yields `CLOSURE_INCOMPLETE`, and cross-revision qualification transfer is permitted only when source closure, runtime closure and qualified capture authority all match.
