### mkaamirerp/trucking-erp — rate-confirmation semantic extraction policy reference
- URL: https://github.com/mkaamirerp/trucking-erp
- Exact commit / revision: 91bd80d52f12120bc3a0dd28b71bbc0569d7df4a
- Date inspected: 2026-09-19
- Status: strong
- What it contains: A no-license FastAPI trucking ERP with a proposed rate-confirmation LLM handoff and unusually detailed deterministic semantic field rules/tests. The handoff preserves page separation and acquisition metadata, treats document text/PDF as untrusted evidence rather than instructions, strips prior role-hint/diagnostic bias from the model input, and requires unsupported values to remain null/uncertain. Tests encode entity-ownership precedence, broker-vs-carrier authority separation, broker-contact cohesion only after role ownership, load-reference labeling and an important distinction between agreed freight rate and broader total carrier compensation/accessorial amounts.
- Rare or undernoticed value: Most public rate-con parsers are regex collections that take the first date/location or largest dollar amount. This repository instead captures the semantic failure modes that make those shortcuts unsafe: entity ownership outranks adjacency, multiple authority numbers are not automatically ambiguous, carrier-owned contact data must not become broker data, and “total carrier pay” is not necessarily the agreed linehaul rate.
- Monetization path: Clean-room reimplement the semantic contract as a high-precision extraction/review policy for freight recovery and carrier-invoice audit. It is especially useful upstream of a deterministic rerating engine because it separates evidence interpretation from price calculation.
- Likely buyer / user: Freight-payment/audit teams, brokers/3PLs, TMS vendors, invoice processors and recovery-service operators.
- Build-time or data advantage: Approximately 1–3 weeks of edge-case discovery and semantic-policy design, plus reduced false-positive recovery risk. Direct source reuse is not authorized.
- Concrete evidence inspected: `app/services/load_parser_openai_handoff_v2.py` builds a page-separated handoff with tenant-identity exclusion, field rules, acquisition metadata, explicit prompt-injection treatment and null-on-unsupported guidance. `tests/test_load_parser_rate_con_field_rules.py` contains focused tests for ownership precedence, rate semantics, authority binding, contact cohesion and removal of tenant/example-specific identities from production rules. Identifying values present in live-like test fixtures were deliberately not copied into this catalog or used as product data.
- License / rights: No license detected in repository metadata at inspection.
- Reuse classification: Inspect / learn / clean-room implementation only unless permission is established.
- Why it is not already obvious / crowded: Zero stars and generic “Trucking ERP” positioning hide a sophisticated extraction-policy layer; the value is buried in semantic rule files/tests rather than marketed as document intelligence.
- Combination opportunities: Clean-room semantics can sit in front of the rights-clean `sutasmantas/invoice-extraction-pipeline` review/provenance layer or a model-assisted parser, then feed the current Qatoto/Kareya contract/rating path. Particularly useful as negative/ambiguity cases in the 20-case freight corpus.
- Next action: Convert only the observed behavioral requirements into an independent test specification—entity ownership, total-pay vs freight-rate, multiple-authority handling, unsupported/null behavior and prompt-injection resistance—and implement those tests without copying source text.
