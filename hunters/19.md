### nikashen/ChronosGuard-TS
- URL: https://github.com/nikashen/ChronosGuard-TS
- Exact commit / revision: `0339dfb8e8ca3fc0f7d0aaace20213f61cc3e176`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: A time-series ML evaluation/replay system with strict Train → ordered Selection → Conformal → frozen Test boundaries, horizon-safe windows, seasonal/Ridge/HGB baselines, per-horizon split-conformal intervals, calibration-only residual alert thresholds, event-level metrics, top-K residual attribution, replay/idempotency/late-data rejection, FastAPI serving and a substantial test suite.
- Rare or undernoticed value: The highest-value asset is not another detector; it is an unusually disciplined **claims/evidence firewall**. The repository preserves negative results, freezes target-free Test forecasts before evaluation, separates blind scoring from annotations, and documents a real release where an independent verifier rejected publication because 33 staging-path fields invalidated the artifact. That is directly transferable to regulated or high-stakes ML release governance.
- Monetization path: Productize the evaluation/provenance gates as a model-release evidence service for forecasting, anomaly detection and predictive-maintenance teams: leakage checks, immutable evaluation artifacts, baseline-vs-candidate comparisons, calibration coverage, event-level false-alarm burden and fail-closed publication receipts.
- Likely buyer / user: ML platform teams, model-risk/governance groups, industrial AI vendors, forecasting/anomaly-detection teams that must defend production claims to enterprise customers or auditors.
- Build-time or data advantage: Compresses months of evaluation-governance engineering around temporal splits, reproducible artifacts, replay, failure-mode reporting, baseline controls and release evidence.
- Concrete evidence inspected: Pinned README at the exact revision; MIT LICENSE; root tree; tests including `test_advanced_artifacts.py`, `test_advanced_forecasting.py`, `test_drift.py`, `test_ett_external_protocol.py`, `test_ett_external_runner.py`, API/CLI/data tests and fresh-wheel smoke coverage. README reports preserved negative results: seasonal-naive beating more complex candidates on synthetic data, NASA anomaly recall paired with thousands of false events, and compact PatchTST beating Ridge on only 1/8 ETT MAE comparisons.
- License / rights: MIT, verified from root `LICENSE`; repository also carries `THIRD_PARTY_NOTICES.md`, so downstream dataset/model-content rights remain separate.
- Reuse classification: Directly reusable subject to MIT terms and separate upstream data/model licenses.
- Why it is not already obvious / crowded: It presents as a portfolio/research project rather than an enterprise model-risk product, while the most commercially valuable behavior is buried in release-verification and negative-result discipline.
- Combination opportunities: Pair with AnoShip for rollout gating/rollback, OctopusTakopi/bocpd or etaia KCP for detectors, and the previously found decision-aligned forecasting stack so models must pass evidence gates before affecting decisions.
- Next action: Extract the evaluation-contract pattern into a model-agnostic benchmark harness and prove it on one non-time-series model release, including a deliberately corrupted artifact that must fail closed.

### rosscyking1115/aerospace-prognostics
- URL: https://github.com/rosscyking1115/aerospace-prognostics
- Exact commit / revision: `66f2d053454fd0868d2effc3897f16c26c933182`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: A substantial prognostics/anomaly platform with CMAPSS RUL workflows, spacecraft anomaly baselines, conformal uncertainty, deployment artifacts/provenance, serving APIs, dashboards, model/prediction registries, SBOM/release-evidence code and an unusually large automated test surface.
- Rare or undernoticed value: Its strongest transferable contribution is **group-aware uncertainty and claim auditing** for repeated measurements. The conformal work calibrates one score per engine/unit rather than pretending correlated cycles are independent, explicitly checks disjoint calibration/evaluation units, reports interval coverage together with width/informativeness, calculates finite-sample attainability, and tests that misleading interval terminology and missing tracked artifacts cannot silently re-enter releases.
- Monetization path: Build a reliability/evidence layer for predictive-maintenance vendors that tells buyers not merely a predicted RUL but whether the stated interval is statistically supportable for independent assets, where coverage fails by subgroup, and whether a release's evidence package is intact.
- Likely buyer / user: Aerospace/industrial predictive-maintenance vendors, fleet analytics teams, insurers/warranty analytics, regulated or safety-sensitive ML product teams.
- Build-time or data advantage: Provides end-to-end reference infrastructure for unit-grouped conformal evaluation, evidence artifacts, deployment provenance, serving and claim tests; potentially months of engineering avoided compared with building evaluation governance around a prognostics model from scratch.
- Concrete evidence inspected: Root MIT license; exact recursive tree at the pinned revision showing `src/aerospace_prognostics/uncertainty/conformal.py`, `experiments/cmapss_conformal.py`, deployment/provenance/SBOM modules, tracked conformal artifacts and extensive tests such as `test_conformal.py`, `test_conformal_artifacts_tracked.py`, `test_interval_naming.py`, `test_claims_ledger.py`, `test_release_provenance.py`, serving tests and CMAPSS phase audits. Commit history for the conformal work explicitly added unit-grouped splits, disjoint-unit leakage guards, calibration variants/attainability and tests against misleading interval claims.
- License / rights: MIT, verified from root `LICENSE`. External aerospace datasets and any third-party model/data artifacts retain their own terms and should not be assumed covered by MIT.
- Reuse classification: Directly reusable software subject to MIT terms; dataset/content reuse requires separate provenance review.
- Why it is not already obvious / crowded: The repository is vertically branded as aerospace prognostics, but the rigorous unit-level uncertainty/claims machinery is reusable in many repeated-measurement domains such as machines, patients, customers and sites.
- Combination opportunities: Combine with ChronosGuard's frozen-Test publication discipline and kernel/BOCPD change detection to create a defensible predictive-maintenance release gate; combine with PyEPO/skwdro only after uncertainty quality is verified.
- Next action: Cleanly separate the domain-neutral grouped-conformal/claims tests and benchmark them on a second repeated-entity dataset to prove the value is not aerospace-specific.

- Reuse classification: Software directly reusable under MIT; benchmark data only after separate rights/provenance verification.
