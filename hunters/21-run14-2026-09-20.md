### Concrete capability
This is much more than a device driver. It runs a SiLA2 gRPC connector and the standard Opentrons robot-server HTTP API **in the same process against one shared OT3 HardwareControlAPI**. A shared lock serializes both interfaces so REST and SiLA callers cannot interleave CAN-bus commands or independently initialize hardware. The embedded robot-server retains its native run/protocol/command surface while the connector becomes the sole owner of underlying hardware cleanup.

The feature estate covers Flex motion, pipetting/nozzle layouts, liquid-level probing and transfer, tip state, gripper control, allowlisted labware/lid movement, deck state, calibration, Heater-Shaker, Temperature Module, Thermocycler, Absorbance Plate Reader and Flex Stacker. Runtime compatibility is intentionally pinned to a validated Opentrons/Python matrix rather than silently assuming cross-version compatibility.

The rare part is the **authority and recovery layer**. `HardwareProxy` serializes module operations through the shared lock; cancellation-sensitive plate-reader work retains ownership until native work settles; cancelled/failed Stacker actions mark recovery-required state and motor deactivation must finish before ownership is released; Stacker labware movement remains blocked until a complete home clears the recovery gate. Emergency halt can preempt a busy shared lock, while ordinary motion remains blocked until re-homing after a halt.

Managed labware movement is also fail-closed. Remote clients cannot supply arbitrary grip coordinates, sensor tolerances or deck occupancy. They select local, provisioned plans; the deck-state ledger is invalidated before physical movement and committed only after completion. Interrupted movement or unclean shutdown requires local reconciliation rather than pretending the previous deck state remains authoritative.

A second unusually valuable layer preserves Protocol Engine authority. During a running Protocol Engine job, direct SiLA actuation and raw robot-server command injection are blocked. Optional controlled mutation is startup-gated to the validated runtime, requires a configured durable ledger plus authenticated/operator-bound access, snapshots authoritative run state, recalculates tip/reagent/capacity effects, allows only bounded command classes at explicit checkpoints/recovery states, and records a hash-chained audit. Ambiguous partial enqueue requires stopping rather than optimistic continuation.

The valuable part is the **strict generation gate** rather than the CLI alone. `test_audit_corpus.py` takes shipped OpenAPI fixtures plus adversarial feature/error corner cases and requires every generated feature set to pass STRICT validation (XSD + authoritative SiLA resolver), specifically protecting against previously observed malformed error/feature structures. - Repository tree: generated example FDL/proto/client/server surfaces plus nontrivial fixtures and test suite.

### Buyer / wedge

First paid wedge: **REST-to-SiLA conversion audit + generated compatibility pack** for one existing instrument API, including mapping-loss report, XSD/semantic validation and a skeleton connector implementation.
