# Hunter 21 — Run 15 — 2026-09-20

## Mission slice
Installed-base lab instrumentation: test whether the `opentrons-flex` pattern generalizes to a second unrelated instrument family, specifically a standards facade over real vendor-native control with simulator/acceptance evidence and safe ownership semantics.

## Explicit hypothesis
A second unrelated scientific-instrument family should exist where a standards interface sits over a real vendor-native protocol/SDK while preserving a single physical actuation authority; if that implementation also ships simulator-to-hardware acceptance evidence, the prior Opentrons finding would support a reusable enterprise category rather than a one-off.

## Discovery modes used
1. **Direct standards + installed-device search:** OPC UA LADS / SiLA 2 + balances, pH meters, pumps and other physical lab hardware.
2. **Code/protocol search:** SICS, SBI, serial command/reply flows, qmix SDK calls, `.sila.xml` feature definitions, device-state and fault handling.
3. **Obscure ecosystem + history archaeology:** low-attention `opcua-lads` repositories and official CETONI submodules; commit-history inspection for race-condition, protocol and result-generation fixes.

## Specialist passes
- **CODE INSPECTOR:** traced balance serial/protocol implementations, real pH serial adapter, CETONI qmix pump calls, command-state/fault handling and available test surfaces.
- **SCIENCE / STANDARDS VALIDATOR:** checked LADS/AFO/ASM semantics and distinguished a standards facade from physical-device validation.
- **COMMERCIAL ANALYST:** evaluated commissioning/upgrade-regression and legacy-instrument standardization wedges.
- **ECOSYSTEM ANALYST:** compared LADS and CETONI against the prior `opentrons-flex` dual-surface architecture.
- **RED-TEAM / VERIFIER:** specifically tried to falsify production readiness, safe concurrent native+standard control, simulator-to-HITL proof and regression evidence.

## DEPRIORITIZED / NEGATIVE KNOWLEDGE
- Generic LADS clients, Node-RED/OPC-UA orchestration examples and simulator-only examples do not close the high-value installed-device boundary unless they include a real native protocol/SDK adapter and failure semantics.
- **Do not equate a standards facade with dual-control arbitration.** In LADS/CETONI the native protocol/SDK is generally underneath the gateway; this is materially different from `opentrons-flex`, which preserved both native HTTP and SiLA control while sharing one hardware authority.
- Simulator availability is not simulator→HITL evidence. A physically realistic simulator is useful, but without an acceptance manifest or hardware validation artifact it does not establish deployment readiness.
- Semantic result output (AFO/ASM) is not equivalent to immutable regulated provenance.
- Absence of tests matters. `lads-server-collection` has an explicit no-test npm script despite meaningful real-device source; this sharply limits evidence quality.

## Hypothesis result
**PARTIALLY SUPPORTED / strict form NOT YET PROVEN.** This run found two independent unrelated families showing that native-protocol/SDK → standards-facade bridges are a real and commercially relevant category. It did **not** find a second repository meeting the full Opentrons conjunction of preserved native control + standards control + one explicit actuation authority + simulator-to-HITL acceptance evidence. Therefore the prior “Dual-Control Authority + Acceptance-Archaeology” skill remains at one full success; do not increment it or promote it from this run.

## Search-policy lesson
**Candidate skill: Native-Protocol Standard-Façade Archaeology**
- **WHEN TO USE:** installed-base laboratory instruments with old serial/vendor SDK control and a desired standards interface.
- **PROCEDURE:** search named instrument/protocol (`SICS`, `SBI`, vendor SDK) + standard (`LADS`, `SiLA`, `OPC UA`); inspect actual command/reply or SDK invocation; inspect state/fault translation; inspect simulator and test/HITL surfaces; then mine history for race, timeout, unit, tare/calibration and result-format fixes.
- **WHY IT WORKED:** device names and standards jargon hide repositories with real integration semantics that generic “lab automation” searches miss.
- **FAILURE MODES:** many repositories stop at simulators or facade schemas and never prove physical acceptance; standards servers may replace rather than safely coexist with vendor-native control.
- **EVIDENCE COUNT:** one productive hunt; **not eligible for SEARCH_SKILLS.md promotion yet**.
