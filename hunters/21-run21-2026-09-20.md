### Concrete capability
`read_chroms()` provides one dispatch surface over internal and external parsers for heterogeneous chromatography/MS formats. At the inspected revision, source and registry code cover or route formats from:
- Agilent ChemStation / OpenLab (`.ch`, `.uv`, `.ms`, `.dx`, `.D`, `.rslt`, related variants),
- Agilent MassHunter DAD,
- Shimadzu LabSolutions / GCsolution / GCMSsolution (`.txt`, `.gcd`, `.qgd`, `.lcd` including PDA, QTOF and triple-quadrupole streams),
- Thermo RAW,
- Waters Empower (`.arw`, `.raw`),
- Varian Workstation `.sms`,
- Chromeleon ASCII,
- Chromatotec `.Chrom`,
- ANDI/netCDF, mzML/mzXML, and Allotrope Simple Model input.

The package can normalize reads into common R objects, attach a canonical metadata/provenance block, and export common outputs including CSV, mzML, ANDI/CDF and ARW; the OpenChrom binding can additionally emit AnIML where that old CLI is available.

### Source / schema verification
The code is not a pile of ad-hoc readers. `R/parser_registry.R` is the declared single source of truth for format extension, directory/batch shape, internal reader, permitted parsers, aliases and fixed parser arguments. The test suite pins this registry against function existence/formals and the historical dispatch table so parser/format permissions cannot silently drift.

`R/metadata_registry.R` defines a canonical cross-format vocabulary for instrument/detector, acquisition software/method/operator/time, sample identity/position/injection information, time/intensity axes, and provenance. The provenance block includes `source_file`, `source_file_format`, `source_sha1`, output/data shape and parser identity. Metadata fields outside the vocabulary are checked during tests/checks. This materially strengthens CAP-013 because the component preserves **where the data came from and how it was read**, not just numerical traces.

### Test verification

- parser-registry invariants;

This is materially stronger than parser smoke tests.
