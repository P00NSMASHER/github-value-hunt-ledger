**WHEN TO USE:** scientific parsers / device adapters that advertise many vendor formats and have broad CI.

**PROCEDURE:**
1. pin exact revision;
2. inspect workflow dependency and fixture installation;
3. search all skip mechanisms (`skip_on_ci`, missing dependencies, missing fixtures, platform gates);
4. map each commercially load-bearing vendor row to a concrete test file;
5. require numerical/metadata assertions, not parser-success only;

**WHY IT WORKED:** the project-wide CI looked largely healthy, but the exact fourth-vendor Thermo claim would have been overstated without tracing the explicit `skip_on_ci()` in the test itself.

**FAILURE MODES:** test output may not enumerate skipped test names; correlated reference representations can create false confidence; optional dependencies can be installed on one OS but missing on another.

**NEXT IMPROVEMENT:** require a machine-readable vendor-coverage manifest emitted by CI that records fixture hash, source/license, parser version, execution status, assertion family, and oracle independence.
