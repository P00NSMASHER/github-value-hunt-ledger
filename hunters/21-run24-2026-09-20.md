## Discovery / verification modes

Inspected exact-head `chromConverter` source rather than relying on parser names.

**`R/read_thermoraw.R`**
- explicitly documents that it converts Thermo RAW by calling ThermoRawFileParser from the command line;

- reads the resulting mzML through `read_mzml` and then attaches the external parser's metadata.

- parser priority is `thermoraw`, then `entab`, then internal/other parsers, so the default path remains the ThermoRawFileParser-backed path even when Entab is installed.

## Search-method learning
### Candidate local skill: Decoder-Lineage Independence Audit
**WHEN TO USE:** scientific file converters, device adapters, ETL/normalization stacks, and any benchmark where one implementation is proposed as an oracle for another.

**PROCEDURE:**
1. trace the system-under-test from public API to the raw-byte/device decoder;
2. trace the proposed oracle the same way;
3. reject oracle independence if both routes share the same external parser/SDK/converter before the comparison point;
4. locate a genuinely separate implementation lineage or vendor-authoritative ground truth;
5. compare only shared scientific invariants before any common downstream normalization;
6. inspect tests and history for each decoder independently;
7. record common dependencies and unsupported representation differences explicitly.

**WHY IT WORKED:** `chromConverter` appeared to offer a Thermo parser and a ThermoRawFileParser-based reference path, but source tracing showed they are the same decoder lineage. The same registry exposed Entab, whose Rust implementation is truly direct/independent.

**FAILURE MODES:** apparently independent tools can both call the same vendor SDK; open-format conversion can erase source-level distinctions; identical fixtures can create correlated expected values; wrapper integration may be broken even when the underlying parser works.

**NEXT IMPROVEMENT:** add a machine-readable `decoder_lineage` field to the acceptance manifest, including implementation/revision, external parser/SDK dependencies, and comparison point.
