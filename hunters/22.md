### 2WKG/flux
- URL: https://github.com/2WKG/flux
- Exact commit / revision: `df98b3fefd165356d0a4a4e05483af4eeda41348`
- Date inspected: 2026-09-19
- Status: watch (exceptionally broad architecture; no reusable license)
- What it contains: A one-star geospatial grid-resilience/digital-twin codebase combining public-data source inventories, DuckDB/Parquet ingestion, utility service-area and county overlays, EIA-861 reliability data, NWS/weather/hazard inputs, an outage-model path, synthetic-grid/pandapower cascade simulation, siting concepts, API/copilot components, scenario/event provenance and extensive validation/test contracts. The source inventory explicitly models one-to-many utility service-area/county overlaps rather than pretending counties map to a single utility.
- Rare or undernoticed value: The strongest value is the evidence discipline around location-to-grid claims: source-authority ledgers, explicit limitations, geospatial crosswalk rules, event-baseline schemas and separate boundaries for where physical simulation is or is not authorized by the available topology. Those are unusually useful clean-room product requirements for defensible grid-risk intelligence.
- Monetization path: Independently implement a property/portfolio grid-resilience product that resolves assets to utility/geography, overlays outage/weather/hazard history, and produces sourced risk/contingency assessments. Sell site-screening or portfolio-risk reports/API access to data centers, industrial facilities, insurers, lenders and resilience consultants rather than offering an unvalidated 'digital twin' claim.
- Likely buyer / user: Data-center/industrial site-selection teams, commercial property owners, insurers, infrastructure investors, utility/resilience consultants, critical-facility operators.
- Build-time or data advantage: Architecture/source research could save roughly 2–5 months of requirements, source-authority mapping and validation-design work, but direct code reuse is unavailable absent a license.
- Concrete evidence inspected: Repository metadata and exact latest commit; `docs/research/minnesota/source-citation-inventory.md` showing utility-service-area → EIA-861 crosswalk and area-weighted county-overlay rules plus limitations; `datasets/catalog.json`; Texas distribution source-authority ledger; `docs/specs/README.md` describing county outage model and weather-driven cascade pipeline; `twin/cascade.py`; event-baseline schema/test docs; merge/test runbooks and many pytest references. The cascade spec itself warns that Texas/ACTIVSg2000 topology does not authorize simulation claims for other states, an important limitation preserved here.
- License / rights: GitHub reports `license: null`; no license grant was established in this inspection. Public upstream datasets referenced by the project each have their own terms. No private or nonpublic data were used or retained.
- Reuse classification: Inspect/learn/clean-room only unless permission is established. Independently source all public datasets and reimplement non-copyrightable methods/specifications.
- Why it is not already obvious / crowded: One star and no repository description despite a large amount of grid/geospatial source research, validation machinery and simulation scaffolding.
- Combination opportunities: Clean-room architecture can be paired with rights-clean CommonGrid database data (subject to ODbL), public EIA/NWS/EAGLE-I-style sources where licensed/available, and permissive power-flow tooling. Particularly interesting as the resilience counterpart to renewable-site/interconnection intelligence.
- Next action: Reproduce only the geospatial claim layer first—100 known locations → utility/territory/county/BA + provenance—and validate against independent sources before attempting any outage/cascade prediction product.

### zymazza/mazzap
- URL: https://github.com/zymazza/mazzap
- Exact commit / revision: `44d15d464e1c3c9a8b48e8b10fdb731369b07673`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: MIT-licensed, region-agnostic 3D land digital-twin engine that ingests DEM/LiDAR, imagery, classified point clouds and arbitrary vector/raster layers; builds vegetation/canopy and survey packages; and runs hydrology, evapotranspiration/water-balance, wildfire, solar and viewshed/horizon analyses. It also includes a non-destructive planning workspace with immutable revisions/branches, scenario reruns over proposed terrain/vegetation changes, MCP/LLM query tooling, live Meshtastic telemetry and offline/local viewer delivery.
- Rare or undernoticed value: The unusual value is not one geospatial algorithm but a coherent site-scale decision stack: public-data acquisition → local digital twin → physical/environmental scenario layers → proposed-land-change revisions → rerun impacts → auditable site query. The repository explicitly exposes model uncertainty instead of presenting all outputs as engineering-grade truth.
- Monetization path: Package a site-diligence/resilience product for renewable/data-center/industrial development, utility wildfire hardening, conservation/land-management planning, insurer engineering surveys or high-value rural property. Sell per-site diligence reports plus recurring monitoring/scenario work rather than a generic 3D viewer.
- Likely buyer / user: Renewable and data-center developers, utility vegetation/wildfire teams, civil/environmental consultants, insurers, land-management firms, conservation organizations and large property owners.
- Build-time or data advantage: Roughly 6–12 months of geospatial ingestion, viewer, scenario-engine, planning/revision and test scaffolding compressed for a focused commercial MVP; more if a buyer requires offline delivery and field-survey integration.
- Concrete evidence inspected: Exact commit and full recursive tree; actual MIT `LICENSE`; 50KB README describing data sources, uncertainty and workflows; `package.json` exposing runnable DEM/imagery/point-cloud ingestion, national-layer acquisition, hydrology, wildfire, ET, solar, viewshed, survey and demo/test commands; implemented pure-NumPy terrain hydrology plus scenario/export code; US-national LANDFIRE/GridMET/climate/WRC adapters; many NATO-country geospatial adapters; large `twin_query.py`/`plan_engine.py` implementations; `hydro_scenario_test.py`, `twin_query_test.py`, `plan_engine_test.py`, wildfire regression, point-cloud and UI/live-store tests plus a mini-twin GeoPackage fixture. `THIRD_PARTY_NOTICES.md` accounts for vendored Three.js/controls/proj4 under MIT, Leaflet under BSD-2-Clause, and original tree meshes.
- License / rights: MIT for repository code and author-created tree meshes. Vendored libraries have MIT/BSD notices. Upstream terrain, imagery, OSM/ArcGIS basemap, LANDFIRE, climate and other government/provider data retain their own source terms and must be audited per deployment.
- Reuse classification: Permissive code reuse subject to MIT plus upstream data/service terms; commercial claims from physical/environmental models require independent validation.
- Why it is not already obvious / crowded: It is marketed as a land digital twin, which hides how much reusable commercial infrastructure sits behind it: ingestion adapters, physical-process engines, immutable planning revisions, provenance/query tooling, offline delivery and field-survey workflows in one repository.
- Combination opportunities: Very strong with `SGridworks/Dynamic-Network-Model`: SGridworks supplies a rights-clean electrical distribution network/AMI/outage/DER test environment while Mazzap supplies terrain, fuels, hydrology, weather/ET and land-change scenarios. Also complements CommonGrid + deployment-gap-model for predevelopment site diligence by adding parcel/site physical-risk and land-constraint intelligence.
- Next action: Build one independent site benchmark from a fresh AOI and run the documented hydrology/wildfire/solar/ET paths against known public references; if reproducible, combine with the SGridworks synthetic feeder environment to demonstrate hazard-aware utility/site planning without requiring private utility data.
