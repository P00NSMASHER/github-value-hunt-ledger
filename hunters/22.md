- Build-time or data advantage: Architecture/source research could save roughly 2–5 months of requirements, source-authority mapping and validation-design work, but direct code reuse is unavailable absent a license.

- Reuse classification: Inspect/learn/clean-room only unless permission is established. Independently source all public datasets and reimplement non-copyrightable methods/specifications.

- Combination opportunities: Clean-room architecture can be paired with rights-clean CommonGrid database data (subject to ODbL), public EIA/NWS/EAGLE-I-style sources where licensed/available, and permissive power-flow tooling. The repository explicitly exposes model uncertainty instead of presenting all outputs as engineering-grade truth.

Sell per-site diligence reports plus recurring monitoring/scenario work rather than a generic 3D viewer.

- Concrete evidence inspected: Exact commit and full recursive tree; actual MIT `LICENSE`; 50KB README describing data sources, uncertainty and workflows; `package.json` exposing runnable DEM/imagery/point-cloud ingestion, national-layer acquisition, hydrology, wildfire, ET, solar, viewshed, survey and demo/test commands; implemented pure-NumPy terrain hydrology plus scenario/export code; US-national LANDFIRE/GridMET/climate/WRC adapters; many NATO-country geospatial adapters; large `twin_query.py`/`plan_engine.py` implementations; `hydro_scenario_test.py`, `twin_query_test.py`, `plan_engine_test.py`, wildfire regression, point-cloud and UI/live-store tests plus a mini-twin GeoPackage fixture. `THIRD_PARTY_NOTICES.md` accounts for vendored Three.js/controls/proj4 under MIT, Leaflet under BSD-2-Clause, and original tree meshes.

### ChelseaKR/wildfire-service-territory-overlap
- URL: https://github.com/ChelseaKR/wildfire-service-territory-overlap
- Exact commit / revision: `aad263fe3d9ede68b90f152463eba46851d2b13c`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: Apache-2.0, reproducible geospatial measurement pipeline joining 132,522 CAL FIRE damage-inspection records to California Energy Commission electric load-serving-entity boundaries, with pinned acquisitions, generated measurement artifacts/reports, county/incident stratification, geometry-repair sensitivity analysis, completeness guards, source-provenance documentation, CI/security/release workflows and offline fixture rebuilds.

That is exactly the kind of uncertainty a site/asset intelligence product usually hides.
- Monetization path: Use as the geospatial attribution/QC layer in a paid wildfire/utility/resilience diligence product: resolve a property/incident to published utility territory with explicit contested/uncertain status, then layer lawful outage, hazard, feeder or customer-authorized network evidence. Sell fixed-price portfolio attribution/risk-data audits first, then recurring monitoring/API.
- Likely buyer / user: Utilities, wildfire/resilience consultants, insurers/lenders, infrastructure investors, data-center/industrial site selectors and energy-data vendors.
- Build-time or data advantage: Roughly 3–6 months of source pinning, robust point-in-polygon attribution, geometry-repair sensitivity, statistical reporting, provenance and fail-closed data-quality engineering for a comparable evidence-grade service-territory layer.
- Concrete evidence inspected: Exact current commit dated 2026-09-18; recursive tree with extensive CI/release/security/provenance/report artifacts; README documenting pinned CAL FIRE/CEC/CDT retrievals, 132,522 records, contested-territory results, geometry-repair counterfactuals and fail-closed acquisition/report rules; actual Apache-2.0 root `LICENSE`.
- License / rights: Apache-2.0 for repository software. CAL FIRE DINS, CEC service-territory layers, CDT county boundaries and any downstream utility/hazard datasets retain their own source terms; public availability does not automatically authorize redistribution. - Value score: A 4/5, B 4/5, C 4/5, D 5/5, E 5/5, F 5/5 = **27/30**. It scores highly because it turns a deceptively simple geospatial join into a defensible uncertainty-aware attribution layer with excellent evidence and rights.
