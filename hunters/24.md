### superzero11/OpenFarm
- URL: https://github.com/superzero11/OpenFarm
- Exact commit / revision: `884a61567dd0d149214090baf9edebc533a2a0df`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: A low-attention, self-hostable precision-ag platform built around FastAPI/PostgreSQL-PostGIS/Celery with field operations, weather and soil workflows, multispectral vegetation-index processing, alerting, field-boundary detection, and ML/remote-sensing jobs. The inspected source includes a centralized vegetation-index registry for NDVI/EVI/SAVI/NDWI and a real Sentinel-2 + FTW field-boundary pipeline: STAC bi-temporal scene search, four-band downloads across two windows, 8-band stacking, FTW segmentation inference, polygonization, area computation and database persistence.
- Rare or undernoticed value: This is not merely an NDVI demo. It already contains much of the operational shell needed for a field-intelligence product: organizations/data models, geospatial storage, async workers, satellite processing, automatic boundary creation, weather/soil tasks and deployment/test scaffolding.
- Monetization path: Package it into a managed crop-health and field-monitoring service for agronomists, crop advisers, specialty-crop operators, insurers/lenders or ag-input distributors. A sharper wedge is automatic field onboarding + recurring satellite anomaly/soil/weather triage, charged per acre/field or as an enterprise monitoring contract.
- Likely buyer / user: Agronomy firms, crop advisers, insurers/lenders, specialty-crop operators, ag retailers/input distributors, regional farm-management providers.
- Build-time or data advantage: Roughly 6–12 months of backend/geospatial/worker/remote-sensing scaffolding compressed for an MVP, although model/data-source terms and production accuracy still need validation.
- Concrete evidence inspected: Exact commit and repository tree; actual BSD-3-Clause LICENSE; GitHub CI with PostGIS-backed backend tests plus frontend build/Docker/smoke-compose; `services/api/app/tasks/indices.py` implementing NDVI/EVI/SAVI/NDWI formulas, Sentinel-2 asset mappings and alert defaults; `services/api/app/tasks/detection.py` implementing STAC search, band download/reprojection, FTW model loading/inference and field polygonization; task tree containing backfill, detection, vegetation, soil and weather workflows.
- License / rights: BSD-3-Clause for repository code. Sentinel/STAC endpoints, FTW model/checkpoint and any third-party datasets/models retain their own licenses/terms and must be checked separately.
- Reuse classification: Permissive code reuse subject to BSD-3-Clause and dependency/model/data rights.
- Why it is not already obvious / crowded: Very low GitHub attention relative to the breadth of actual implementation; source depth is substantially greater than its repository visibility suggests.
- Combination opportunities: Particularly strong with `RS-iCM/RSCM` for crop/non-crop bootstrapping, `Smart-Farming-Lab/logistics_maps` for operational agronomy layers, hydrology/ET findings for irrigation stress, and weather/climate adapters for risk-triggered scouting. OpenFarm can be the operational shell while specialized models supply differentiated intelligence.
- Next action: Stand up the pinned commit against a small lawful Sentinel-2 test area, measure boundary quality and index/alert reproducibility, and audit FTW/model/source terms before including field-boundary inference in a commercial pilot.

### RS-iCM/RSCM
- URL: https://github.com/RS-iCM/RSCM
- Exact commit / revision: `7c48c6c93d758c72aceb99e9923181a77b7c51cb`
- Date inspected: 2026-09-19
- Status: strong (current upstream / materially stronger validation evidence for the RSCM family)
- What it contains: MIT-licensed end-to-end crop/non-crop mapping from Sentinel-2 time series using robust sample generation without requiring external training samples, with single-field/batch workflows, reproducibility code, real Sentinel example artifacts, shapefiles and classification outputs.
- Rare or undernoticed value: A label-light way to bootstrap crop-area intelligence where proprietary field/crop labels are unavailable. The current organization repository documents an independent AgriFieldNet evaluation across 18 countries and ships enough example artifacts to examine outputs rather than relying on a paper abstract alone.
- Monetization path: Use as a crop-presence/field intelligence layer for ag lending/insurance, land-use monitoring, input-sales territory intelligence, acreage estimation and automatic onboarding of farm-monitoring products.
- Likely buyer / user: Crop insurers, ag lenders, remote-sensing/ag-intelligence vendors, input distributors, sustainability/land-use monitors, public-sector agriculture programs.
- Build-time or data advantage: Could save 3–6 months of crop-mask/sample-generation/model workflow work in geographies where labeled field data are the bottleneck.
- Concrete evidence inspected: Exact commit, recursive tree with `RSCM_v1.py`, `reproduce_results.py`, real Sentinel-2 L2A bands/classification outputs/testing field shapefiles and validation artifacts; README methodology/evaluation; actual MIT LICENSE. README reports AgriFieldNet precision/recall/F1 of 0.8783/0.8738/0.8760 across 18 countries; this remains author-reported until independently reproduced.
- License / rights: MIT for repository code. Sentinel/example-data and paper/artifact rights must still be treated separately where applicable.
- Reuse classification: Permissive code reuse subject to MIT and source-data terms.
- Why it is not already obvious / crowded: Single-digit stars despite tackling the expensive label/bootstrap problem rather than simply calculating vegetation indices.
- Combination opportunities: Already compatible conceptually with the ledger's earlier RSCM-family combinations; the strongest new pairing is `OpenFarm` as operational shell + RSCM for crop-mask bootstrapping + irrigation/weather/soil layers for ongoing decisions.
- Next action: Reproduce the evaluation on a small independently sourced Sentinel-2 + known-field test set before relying on the reported cross-country accuracy in commercial claims.
