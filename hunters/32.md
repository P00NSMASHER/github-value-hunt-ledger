### rodrigo-arenas/pyworkforce
- URL: https://github.com/rodrigo-arenas/pyworkforce
- Exact commit / revision: `ca4892502d2d92cc996c9fde96293ff90b560426`
- Date inspected: 2026-09-19
- Status: **strong — top find in this lane**
- What it contains: A practical workforce-planning library spanning Erlang C/A/B queue staffing, multi-skill staffing, shift scheduling, named rostering and break scheduling, using OR-Tools constraint programming behind consistent Python APIs.
- Rare or undernoticed value: It covers most of the mathematical planning pipeline from demand volume to individual work plans instead of solving only one narrow scheduling step. The combination of queuing math plus skill mix plus roster/break optimization is unusually product-ready for a lightweight library.
- Monetization path: Build a workforce-planning overlay for contact centers/service desks that ingests demand forecasts and outputs required FTE, skill mix, shifts, named rosters and break plans; sell scenario planning, labor-cost reduction and service-level assurance rather than a generic scheduler.
- Likely buyer / user: Contact centers, BPOs, customer-support operations, healthcare/retail/service operations with variable demand and finite skilled labor.
- Build-time or data advantage: Estimated **2–6 months** saved on solver implementation, numerical validation, scheduling/rostering primitives and tests versus building the stack from scratch.
- Concrete evidence inspected: `pyworkforce/queuing/erlang.py` implements required-position calculations using service level, max occupancy, ASA, AHT, interval and shrinkage; docs expose `MultiSkillStaffing` and `MinHoursRoster`; `pyworkforce/breaks/break_scheduler.py` implements a CP-SAT break scheduler that preserves minimum coverage; dedicated break-scheduler tests exist; current contributor docs explicitly describe queue staffing → multi-skill staffing → shift scheduling → rostering → break scheduling and require focused tests/independent validation for models.
- License / rights: MIT, copyright Rodrigo Arenas. No external workforce data was copied.
- Reuse classification: **Directly reusable** under MIT with notice preservation.
- Why it is not already obvious / crowded: It looks like a Python utility package rather than a commercial WFM system, but internally it already contains the difficult decision-science core that many WFM products wrap in UI/integrations.
- Combination opportunities: Combine with the clean-room operational requirements learned from `davescalante/LCC-WFM`; feed ticket-arrival/category forecasts from support triage models into skill-specific staffing; pair with evidence/benchmark tooling to quantify labor savings versus current schedules.
- Next action: Build one end-to-end reproducible benchmark: half-hourly demand + AHT + SLA → required positions → skill mix → shifts → named roster → breaks, then compare labor hours and SLA coverage with a naive spreadsheet baseline.

### lucamarx/pywfplan
- URL: https://github.com/lucamarx/pywfplan
- Exact commit / revision: `11f12beaf4662c2ba3286eb50f6623e6a1914492`
- Date inspected: 2026-09-19
- Status: **strong complementary reusable planner**
- What it contains: An archived but MIT-licensed Python/C++ call-center weekly planner derived from an earlier production system. Agent scheduling constraints are expressed compositionally as shift regular expressions, converted to finite-state machines that sample valid plans; simulated annealing then minimizes staffing-curve error plus an agent-comfort objective.
- Rare or undernoticed value: This attacks a different layer than `pyworkforce`: instead of primarily solving staffing/rostering with standard constraint models, it offers an elegant way to encode **complex per-agent legal/contract/availability patterns as a language of valid schedules**. The author states the predecessor was used in production for call centers of roughly 50–200 agents; that claim is recorded as author-provided context, not independently verified.
- Monetization path: Incorporate the schedule-language/FSM pattern into the WFM assurance/challenger concept so customer-specific contract rules and recurring availability patterns can be represented compactly, then compare optimized staffing error/labor hours against current schedules.
- Likely buyer / user: Mid-sized contact centers/BPOs with heterogeneous contracts, part-time schedules and recurring availability rules.
- Build-time or data advantage: Estimated **3–6 weeks** saved on designing a compact agent-rule representation, schedule sampler and alternative heuristic optimizer; `pyworkforce` remains the preferred primary decision-science stack because it is broader and more actively maintained.
- Concrete evidence inspected: README at pinned revision; full recursive tree; `src/staff_planner.cpp`. The source constructs per-agent FSM samplers from regular-expression shift rules, calibrates staffing vs comfort energy, runs simulated annealing and reports target vs simulated staffing by day. The repository includes multiple substantial example agent/shift/target datasets and planning notebooks, Python bindings and C++ optimizer/FSM/regex code. No dedicated test suite was evident in the inspected tree, which lowers production confidence.
- License / rights: **MIT**; repository is archived and points ongoing development to Codeberg. Example data rights should be treated separately unless provenance is established.
- Reuse classification: **Directly reusable under MIT**, with normal notice obligations; prefer selectively reusing concepts/components rather than depending on an archived package unchanged.
- Why it is not already obvious / crowded: Only ~3 GitHub stars and archived status obscure a planner whose architecture came from a claimed real production predecessor and contains significantly more algorithmic depth than its attention suggests.
- Combination opportunities: `pyworkforce` for Erlang/multiskill/roster/break optimization + `pywfplan` schedule-language/FSM ideas for contract-pattern validity + LCC-WFM clean-room reconciliation requirements. That could yield a particularly strong “schedule challenger” rather than a monolithic WFM replacement.
- Next action: Recreate 3–5 representative contract/availability patterns in both pywfplan and a clean CP-SAT model, benchmark feasibility/runtime/coverage, and retain only the FSM approach if it materially improves expressiveness or search speed.
