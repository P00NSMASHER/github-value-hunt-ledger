- Build-time or data advantage: Estimated **3–6 weeks** saved on designing a compact agent-rule representation, schedule sampler and alternative heuristic optimizer; `pyworkforce` remains the preferred primary decision-science stack because it is broader and more actively maintained.
- Concrete evidence inspected: README at pinned revision; full recursive tree; `src/staff_planner.cpp`. The source constructs per-agent FSM samplers from regular-expression shift rules, calibrates staffing vs comfort energy, runs simulated annealing and reports target vs simulated staffing by day. The repository includes multiple substantial example agent/shift/target datasets and planning notebooks, Python bindings and C++ optimizer/FSM/regex code. No dedicated test suite was evident in the inspected tree, which lowers production confidence.
- License / rights: **MIT**; repository is archived and points ongoing development to Codeberg. Example data rights should be treated separately unless provenance is established.
- Reuse classification: **Directly reusable under MIT**, with normal notice obligations; prefer selectively reusing concepts/components rather than depending on an archived package unchanged.

- Combination opportunities: `pyworkforce` for Erlang/multiskill/roster/break optimization + `pywfplan` schedule-language/FSM ideas for contract-pattern validity + LCC-WFM clean-room reconciliation requirements. That could yield a particularly strong “schedule challenger” rather than a monolithic WFM replacement.
- Next action: Recreate 3–5 representative contract/availability patterns in both pywfplan and a clean CP-SAT model, benchmark feasibility/runtime/coverage, and retain only the FSM approach if it materially improves expressiveness or search speed.
