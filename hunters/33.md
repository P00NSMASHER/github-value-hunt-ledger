### Grashjs/cmms (Atlas CMMS)
- URL: https://github.com/Grashjs/cmms
- Exact commit / revision: `869d648f028057d637ccb66b740f4499a097c2fc`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: Mature self-hosted CMMS spanning web/mobile/backend. Documented implemented workflows include work-order creation/assignment/history, time/priority tracking, automated triggers, maintenance analytics, equipment/downtime/cost tracking, inventory/stock alerts, purchase-order approvals, roles/workflows, locations and service requests. The deployment includes Spring Boot, React/TypeScript, React Native, Docker and PostgreSQL-era infrastructure, with current commits and production-oriented configuration.
- Rare or undernoticed value: A broad, functioning facilities/maintenance operating system that can supply much of the commodity asset/work-order/inventory/mobile substrate for a more differentiated building-operations product. It is much more complete than the typical “CMMS demo” repository.
- Monetization path: Facilities-management SaaS/services; predictive/decision layer on top of work-order history; property-portfolio maintenance operations; contractor/vendor dispatch; building-system compliance and cost analytics. A proprietary commercial product should account for the license model rather than simply embedding the code.
- Likely buyer / user: Facilities managers, property operators, manufacturers, schools/campuses, healthcare facilities, hotels and public-building operators.
- Build-time or data advantage: Very high if AGPL/commercial-license terms fit the deployment; likely saves many months of work-order, asset, inventory, role, reporting and mobile plumbing. Even as a clean-room reference, it is a strong canonical workflow map.
- Concrete evidence inspected: Exact latest commit; root contents; `README.MD` with implemented feature/deployment stack and mobile support; repository `LICENSE`/commercial-license files present; code-oriented discovery surfaced work-order, meter and purchase-order concepts in source/localization surfaces. The latest commit shows active environment/deployment maintenance as of 2026-09-16.
- License / rights: Dual-license posture documented by the project: AGPLv3 for open-source use plus a separate commercial license for white-label/advanced commercial features. Treat proprietary SaaS reuse as a deliberate licensing decision.
- Reuse classification: Reusable under AGPLv3 conditions, or under a separately obtained commercial license; otherwise inspect/learn/clean-room concepts.
- Why it is not already obvious / crowded: Search results surface it as one of many CMMS projects, but inspection shows a maintained multi-platform product with procurement, inventory, analytics, automation and mobile operations rather than CRUD-only work orders.
- Combination opportunities: Add public property/building data from PermitPlate, energy/BMS telemetry adapters, anomaly detection and contractor opportunity scoring to create a facilities intelligence layer instead of reselling a generic CMMS.
- Next action: Map which Atlas entities/events would be needed for a read-only “maintenance intelligence” layer and test whether keeping the differentiating analytics outside the AGPL application can satisfy the desired product/licensing architecture.

- Date inspected: 2026-09-19
- Status: watch

The work-order factory centralizes threshold, scheduled, predicted-surge, predicted-ETA and end-of-day reasons with priority and human-readable evidence; project docs describe the sensor→prediction→dispatch loop.

It gives a concrete workflow for comparing fixed schedules against condition/prediction-triggered service.
- Monetization path: Facilities labor optimization proof-of-concept; condition-based janitorial/service dispatch; reusable demo/decision layer for facilities vendors considering sensor-to-work-order automation. It is not by itself a production CMMS.
- Likely buyer / user: Facilities managers, outsourced janitorial/FM companies, airports/offices/venues with occupancy and consumable sensors, building-operations technology providers.
- Build-time or data advantage: Medium. Saves time on simulation, predictive-dispatch UX and work-order explanation patterns, but production value depends on integrating real telemetry and a real CMMS/service platform.
- Concrete evidence inspected: Exact latest commit; recursive tree with simulator, work-order ticket and Playwright setup; root MIT license; `src/simulation/workorder.ts` central work-order factory and reason/priority mapping; README/code-search evidence for predictive dispatch and tests; conditions-based-maintenance design document.
- License / rights: MIT license verified. Any integration with Mapped's separate commercial platform/connectors has its own terms and is not implied by this repository's MIT license.
- Reuse classification: Directly reusable under MIT terms for repository code.
- Why it is not already obvious / crowded: It looks like a narrow restroom demo, but the generalizable part is an explainable condition/prediction→work-order state machine that can be transplanted to other facilities service categories.
- Combination opportunities: Pair with Atlas CMMS or a customer CMMS export, BMS/occupancy telemetry, and the existing facilities SLA/asset model to test whether predictive dispatch measurably reduces unnecessary service visits without missing SLA/cleanliness thresholds.
- Next action: Treat as a benchmark/demo component, not a new standalone business. Run a simple cost model comparing fixed schedules vs threshold/predictive dispatch and require observed service-labor savings before promoting it beyond watch status.

### JpAbg/CAFM
- URL: https://github.com/JpAbg/CAFM
- Exact commit / revision: `32b72dee32841ba18191698a463b79e26a30384e`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: Active MIT-licensed CAFM application for Frappe/ERPNext/HRMS. The work-order implementation distinguishes corrective vs preventive work, derives records from maintenance requests or preventive plans, blocks duplicate active/preventive occurrences, tracks planned dates and SLAs, carries required checklists/inspection templates, supports internal technician vs external vendor assignments, validates service contracts/quotations, synchronizes maintenance history and checks asset warranty status before work proceeds.
- Rare or undernoticed value: This is a more permissive facilities substrate than the AGPL-heavy CMMS alternatives. Warranty-aware dispatch and preventive-occurrence deduplication are particularly valuable because they prevent avoidable service spend rather than only recording completed work.
- Monetization path: Facilities work-order/PM SaaS; warranty-leakage prevention; vendor-service governance; portfolio maintenance operations; embedded maintenance module behind a higher-value building intelligence product.
- Likely buyer / user: Property managers, schools/campuses, healthcare, hotels, outsourced FM providers and organizations already using or willing to use ERPNext/Frappe.
- Build-time or data advantage: High. Reuses a mature ERP substrate plus real facilities-specific business rules, assignment, inspection and service-contract logic; could save months versus building a work-order/PM core from scratch.
- Concrete evidence inspected: Exact current commit; `README.md` with clean-site installation/test instructions and Frappe/ERPNext/HRMS dependencies; repository `license.txt`; `cafm/cafm/doctype/facility_work_order/facility_work_order.py` showing source inference, PM population, warranty lookup, duplicate-work prevention, service-contract validation, SLA updates and maintenance-history synchronization.
- License / rights: MIT verified for this repository. Frappe/ERPNext/HRMS and other dependencies retain their own licenses and must be reviewed for a combined commercial deployment.
- Reuse classification: Directly reusable under MIT terms for repository code, subject to dependency-license architecture.
- Why it is not already obvious / crowded: The repository is young and low-profile, but its work-order file already contains substantially more facilities-specific validation than generic CRUD CMMS demos.
- Combination opportunities: Add AssetOpsBench telemetry/failure-mode reasoning or sim-restroom condition triggers upstream; create work orders only when evidence warrants them, then use warranty/service-contract checks to route the economically correct fulfillment path.
- Next action: Benchmark one closed-loop scenario—sensor/condition alert → work-order creation → warranty/service-contract routing → completion—and quantify avoided truck rolls or vendor spend before elevating a facilities product thesis.
