## Mission

## Catalog rule
Record every meaningful candidate inspected in this file. For strong candidates, include detailed evidence. For weak/rejected candidates, record a concise reason so future runs do not repeat the work.

- Publicly visible is not automatically public domain.

- No-license code is inspect/learn/clean-room only unless permission is established.
- Do not collect, reproduce, preserve, or exploit credentials, private/personal data, authentication material, accidentally exposed confidential information, or leaked trade secrets.
- Do not exploit vulnerabilities or unauthorized access paths.

### freeacs/freeacs
- URL: https://github.com/freeacs/freeacs
- Exact commit / revision: `f4c5d056ac6c247e0757de20acacd6046fd0ef0d`
- Date inspected: 2026-09-19
- Status: strong
- What it contains: Full TR-069/CWMP Auto Configuration Server stack with device sessions, provisioning decisions, parameter reads/writes, firmware/download logic, scheduled kicks, XML/SOAP parsing, basic/digest/no-security modes, DB/core modules, Docker/deployment assets, and a web/service ecosystem.
- Rare or undernoticed value: This is operational ACS infrastructure rather than a sample library. The `tr069` module alone contains request/decision/response strategies for Inform, GetRPCMethods, GetParameterNames/Values, SetParameterValues, Download, Reboot, FactoryReset and TransferComplete plus substantial integration tests and fixture traffic.
- Monetization path: Hosted/managed ACS for ISPs and WISPs, legacy FreeACS migration/modernization, fleet provisioning analytics, CPE compliance/regression testing, or a managed TR-069-to-newer-device-management transition service.
- Likely buyer / user: Regional ISPs/WISPs, CPE/router vendors, managed service providers, telecom labs, broadband operators with legacy CWMP fleets.
- Build-time or data advantage: Saves many months of protocol/session/provisioning logic and test-fixture creation; existing code includes complex device-state and service-window logic that would be expensive to recreate safely.
- Concrete evidence inspected: Exact revision tree for `tr069/src` shows `Tr069Controller`, CWMP version/session classes, provisioning strategies, Get/Set parameter decision/request/response implementations, download/reboot/factory-reset/transfer-complete handling, SOAP/XML parser structures, authentication modes and background kick/device-detection tasks. Test tree contains provisioning tests for basic/digest/no-security modes plus XML fixtures for Inform, GetParameterNames, GetParameterValues, GetRPCMethods and SetParameterValuesResponse.
- License / rights: MIT; root and `tr069` module both contain license files. Preserve MIT notices and audit third-party dependencies.
- Reuse classification: permissive reusable code, subject to MIT/dependency terms.
- Why it is not already obvious / crowded: Mature telecom OSS that is less fashionable than cloud-native/USP tooling; its value is concentrated in legacy broadband estates where replacement labor is painful and buyer urgency is operational rather than developer-driven.
- Combination opportunities: Pair with a CPE simulator such as `Viasat/cwmp-cpe-horde` conceptually, and with official BBF data-model definitions, to create a TR-069 fleet validation/migration lab. Can also combine with existing network inventory/validation findings in this lane.
- Next action: Stand up the permissive stack in an isolated lab, measure deployment friction/current dependency health, and scope a modern managed wrapper with tenant isolation, observability, secure defaults and USP/TR-369 migration assistance.
