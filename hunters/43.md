### dparo/master-thesis — branch-and-cut CVRP pricing engine
- URL: https://github.com/dparo/master-thesis
- Exact commit / revision: `5d89745d240cd8516e592fa13d4d64b929f54032`
- Date inspected: 2026-09-19
- Status: watch
- What it contains: A C implementation of a Mixed Integer Programming / branch-and-cut solver for the Capacitated Profitable Tour Problem used as a pricing subproblem in column-generation CVRP methods, with CMake build, VRPLIB parsing, max-flow / Gomory-Hu machinery, MIP components, sample data, and a substantial C test corpus.
- Rare or undernoticed value: This is not another heuristic route demo; it exposes exact-optimization infrastructure around the hard pricing step that appears inside state-of-the-art vehicle-routing decomposition schemes. That makes it a useful benchmark/reference for situations where route quality is worth more than millisecond response time.
- Monetization path: Embed or reimplement the relevant pricing/route-quality techniques in a high-value dispatch optimizer for dense fleet operations, or sell solver-backed route-quality benchmarking to logistics software vendors that currently rely on simpler heuristics.
- Likely buyer / user: Routing/TMS vendors, industrial fleet operators, parcel/fuel/waste distribution firms, OR consultancies.
- Build-time or data advantage: Several weeks to months of algorithm engineering and test scaffolding are already represented, but production use still requires integration work and solver licensing analysis.
- Concrete evidence inspected: README build/run/test instructions; root CMake/dependency structure; `tests/` with `test-core.c`, `test-gomory-hu-tree.c`, ~20 KB `test-maxflow.c`, `test-mip.c`, parser and VRPLIB tests; exact revision metadata.
- License / rights: Project MIT; listed bundled dependencies are MIT/BSD/public-domain. Runtime/build requires IBM CPLEX >=12.10, whose separate commercial licensing is a material deployment constraint.
- Reuse classification: Permissive project code, subject to MIT terms and separate CPLEX / third-party obligations.
- Why it is not already obvious / crowded: It is packaged as a master's-thesis repository with 16 stars and research terminology rather than as a commercial routing SDK; the valuable artifact is the low-level pricing solver/test machinery.
- Combination opportunities: Pair conceptually with `open_tms` for a premium route-optimization module or with multi-trip/time-window scheduling references from the no-license catalog; use as a benchmark against simpler OR-Tools/heuristic solutions before investing in an exact engine.
- Next action: Reproduce benchmark instances with an independently licensed solver path and quantify route-quality/runtime gain versus a modern OR-Tools baseline before commercial prioritization.

- Likely buyer / user: Route-based distributors and inventory-heavy field-service operators.

- Reuse classification: Copyleft; direct reuse requires GPL compliance. Safer commercial use may be as research/reference unless the product can accommodate GPL obligations.
- Why it is not already obvious / crowded: Academic thesis framing and age hide the useful inventory-routing formulation, but commercial maturity is low.
- Combination opportunities: Compare with deterministic route/stock optimization engines; potentially combine its problem formulation with modern forecasting and routing components rather than its old implementation.
