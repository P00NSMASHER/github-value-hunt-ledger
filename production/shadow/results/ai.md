## Run 1 — 2026-09-20

HYPOTHESIS: Durable agent runtimes become materially more valuable when every external effect is forced through a recorded host boundary with strict deterministic replay, fail-loud divergence, crash resume, approval pauses, and single-writer state protection. A runtime that can turn a recorded run into a no-live-effects regression fixture should materially compress long-horizon reliability and verification engineering compared with graph/checkpoint-only frameworks.

DISCOVERY METHODS: (1) direct domain search for durable/resumable agent runtimes and checkpoint/replay systems; (2) code-level search around `checkpoint`, `resume`, `call log`, `host call`, replay divergence, approvals, strict verification, and run leases; (3) ecosystem/comparator search across deterministic-replay and workflow/runtime families, including Atmosphere's multi-runtime AI governance layer; (4) recent commit/history archaeology for reliability defects, release failures, CI hardening, and concurrency fixes. Specialist decomposition: CODE INSPECTOR traced the replay journal, source/argument divergence and strict fixture semantics; RELIABILITY/ECOSYSTEM analyst checked lease/storage behavior and compared adjacent runtimes; COMMERCIAL ANALYST scoped a reliability-retrofit wedge; independent RED-TEAM/VERIFIER reviewed the frozen evidence without using the proposed score and attempted to reduce the thesis to commodity workflow durability.

CLAIM / EVIDENCE PACKET:
- IMPLEMENTED + TESTED: durability is based on deterministic replay of an effect journal rather than only process-memory/checkpoint restoration. Host effects are deterministically keyed, live results are journaled, and restore re-evaluates the bundle while feeding prior results until the live frontier. `crates/chidori-js/src/replay.rs` explicitly detects bundle changes and treats edits to already-journaled behavior as divergence rather than silently substituting new side effects.
- IMPLEMENTED + TESTED: `crates/chidori-js/tests/replay.rs` contains concrete record→fresh-runtime replay, suspend→persist→restore→resume, post-frontier modify-and-resume, pre-frontier fail-loud divergence, memoized deterministic-step replay, and independent-restored-runtime tests. The replay test deliberately avoids re-performing previously recorded effects; the divergence test errors when an already-executed host call changes.
- IMPLEMENTED: the strict verification workflow in `docs/replay.md` requires a source snapshot manifest, disables providers/tools, uses an untrusted policy posture, refuses source drift, enables strict replay so a journal miss cannot silently execute live, ignores the lax-replay escape hatch, requires the full journal to be consumed, refuses pauses/incomplete runs, detects unexpected live calls, and checks byte-identical output. Export refuses incomplete/leased/paused runs.
- IMPLEMENTED: crash continuation preserves the original run ID, persisted host promises, approvals, VFS, signals and policy state. Server resume/signal/approve paths use a run lease and return 409 Conflict to a second writer before it mutates durable state.
- IMPLEMENTED: powerful tool/network/workspace effects are approval-gated by default; unattended untrusted execution fails closed unless the operator explicitly selects trusted mode.
- PROVENANCE: root license is Apache-2.0. The inspected head is the 2026-08-30 v3.8.1 release-fix commit.
- HISTORY / NEGATIVE EVIDENCE: the same head documents that v3.8.0 shipped npm/PyPI packages while crates.io/binary publication failed due to an engine `TypeofBr` panic plus an out-of-sync internal crate, and that main CI had accumulated unrelated failures. v3.8.1 adds regression and pre-publish drift checks, but this is evidence of a young runtime with real release-engineering risk, not a mature infallible substrate.

CLAIMS NOT VERIFIED / LIMITS:
- Distributed single-writer safety is backend-dependent. The repository documentation says run leases are advisory on filesystem and S3 stores; stronger exclusion is available on stores such as SQLite/cell-store/Durable Objects. Do not claim universal exactly-once execution from the lease feature.
- The replay guarantee only covers effects mediated through the runtime boundary. Workspace state remains real disk; recorded writes can be re-materialized during verification, and external behavior bypassing the host boundary cannot be magically replayed.
- Normal replay has an explicit `CHIDORI_REPLAY_LAX=1` compatibility escape hatch for argument divergence; the dedicated `chidori verify` path is stricter and ignores that escape hatch.
- I did not independently rerun the repository test suite. A local clone/test setup attempt was blocked by the execution sandbox's lack of outbound DNS, so TESTED means committed tests were inspected rather than rerun here.
- Production-scale throughput, multi-region durability, compatibility with arbitrary Node/Python agent ecosystems, and realized customer reliability savings were not independently established.

INDEPENDENT RED-TEAM / VERIFIER: PASS_WITH_LIMITS. The strongest commodity objection is that Temporal, DBOS, AWS durable-execution systems and agent checkpoint frameworks already solve durable workflows or resumable state. Chidori's non-commodity value is narrower: an agent-specific effect boundary plus zero-model-call deterministic replay, strict source/argument divergence, a no-live-effects CI fixture contract, human pause/resume, and explicit single-writer continuation. The thesis should therefore be “replayable agent execution and verification,” not merely “durable agents.” The strongest operational objection is the custom embedded JavaScript runtime and backend-dependent lease semantics; migration/integration burden could erase the benefit for teams already deeply invested in Temporal/LangGraph-style stacks. Recent release/CI defects lower evidence/operational confidence and prevent an unqualified PASS.

COMMERCIAL WEDGE: Sell a fixed-price **Replayable Agent Reliability Retrofit** to AI platform/application teams operating a high-value tool-using agent. Wrap one workflow's model/tool/API effects behind the runtime boundary; deliver strict replay fixtures, crash/resume and approval-gate tests, source-drift evidence, and duplicate-driver tests. The money path is lower incident MTTR, less repeated model spend during debugging, reduced duplicate side-effect risk after crashes/retries, and faster deterministic regression testing. A first paid engagement appears feasible on a weeks-scale integration rather than requiring a full platform replacement, but customer migration cost is the gating variable.

COMPARATOR: `Atmosphere/atmosphere@5eaac40919357742ac0d67c59840d0b6eb909d53` provides independent adjacent evidence that agent-runtime value is moving toward portable governance, capability contracts, approvals, passivation/cancellation, signed runtime capability manifests and fail-closed safety across many AI frameworks. It is broader than Chidori, while Chidori's inspected evidence is deeper on deterministic side-effect replay and recorded-run verification. VALUE HANDOFF:
1. CAPABILITY DELTA: a reusable deterministic agent-run evidence primitive becomes available: journal every mediated side effect, reconstruct a run without live external actions, fail on source/argument drift, and continue safely at the frontier after crash or human pause.
2. GRAPH EDGE: directly strengthens the production architecture's restart/recovery, verifier reproducibility, approval gating and lease-recovery requirements. It could serve as a candidate worker-runtime primitive if its backend and execution-model limitations survive a dedicated integration test.
3. RADAR SIGNAL: deterministic replay is converging from generic durable-workflow systems into agent-specific runtimes where model/tool calls are first-class recorded effects; Atmosphere independently shows adjacent convergence around governance/capability contracts.
4. EXPERIMENT IMPACT: restart, lease-conflict, approval fail-closed, evidence mutation/source drift and no-live-effects regression tests become substantially cheaper to make falsifiable because a recorded run can act as a deterministic fixture.
5. COMMERCIAL IMPACT: specific buyer is an AI platform/application team with expensive nondeterministic tool-using workflows; first wedge is a reliability retrofit rather than wholesale orchestration replacement; moat comes from the combined effect journal + strict replay verifier + source/argument provenance + operational continuation semantics.
6. NEGATIVE KNOWLEDGE: “checkpoint/resume” alone is not evidence-grade durability. Future AI-runtime searches should require side-effect authority boundaries, fail-loud divergence, a strict no-live replay mode, crash/frontier tests, explicit human-approval semantics, and storage-specific concurrency guarantees before awarding strong reliability credit.

## Run 2 — 2026-09-20

HYPOTHESIS: The most important missing semantic in replayable agent runtimes is the **ambiguous-effect window**: once a non-idempotent external call may have committed but its acknowledgement was lost, a safe runtime must not infer failure and retry. A compact runtime that persists intent before I/O, distinguishes completed versus indeterminate outcomes, parks indeterminate writes for actor-attributed evidence, and keeps model approval authority outside the model can materially improve money-mutating or otherwise irreversible agent workflows even if it is not a full distributed scheduler.

DISCOVERY METHODS: (1) direct search for durable/resumable tool-calling agent runtimes with event sourcing, approvals, crash recovery and non-idempotent side-effect semantics; (2) code/phrase search around `TOOL_EXECUTION_STARTED`, `TOOL_OUTCOME_UNKNOWN`, `awaiting_recovery`, replay divergence, actor/evidence resolution and fail-closed planner parsing; (3) low-attention discovery deliberately emphasizing zero-star and newly published runtimes; (4) adjacent ecosystem comparison against deterministic record/replay libraries and independent durable-tool documentation; (5) commit-history archaeology to identify when ambiguity handling and model-planner hardening entered the candidate. Specialist decomposition: CODE INSPECTOR traced event folding, tool start/outcome ordering, approval authority and recovery; RELIABILITY ANALYST inspected journal/concurrency semantics and failure windows; COMMERCIAL ANALYST mapped the semantics to financial/customer-facing side effects; independent RED-TEAM/VERIFIER received the claim packet without the score and attempted to disprove novelty, multi-writer safety and evidence integrity.

EVIDENCE SNAPSHOT: `shadow-ai-20260920-agent-runtime-3d4c3bf5`

CLAIM / EVIDENCE PACKET:
- IMPLEMENTED + TESTED: `src/agent_runtime/runtime.py` persists planner decisions and `TOOL_EXECUTION_STARTED` before entering the handler. Completed outcomes are replayed from the journal rather than re-executed. For a non-idempotent tool with a recorded start but no durable terminal outcome, the runtime emits `TOOL_OUTCOME_UNKNOWN` and returns `AWAITING_RECOVERY` instead of retrying.
- IMPLEMENTED + TESTED: `tests/test_durability.py::test_crash_after_non_idempotent_start_parks_for_evidence_not_retry` constructs the exact dangerous crash window, marks the simulated external email as possibly committed, advances the run twice, proves the side effect is not repeated, and requires `resolve_tool_outcome` with non-empty actor and evidence before continuation. Duplicate manual resolution is rejected.
- IMPLEMENTED + TESTED: cold restart uses a fresh runtime/planner against the same SQLite journal; the completed effectful tool is not re-executed and the replacement planner receives zero calls. Approval state likewise survives restart, and a denied approval becomes tool feedback rather than an execution bypass.
- IMPLEMENTED + TESTED: the model-backed planner cannot self-approve gated tools. Tests feed model output containing `approved: true` / `human_approved_by` fields and the runtime still stops before the tool. Malformed model output raises `PlannerError` instead of being converted into `RUN_COMPLETED` success.
- IMPLEMENTED: `src/agent_runtime/journal.py` is insert-only for events, uses `(run_id, seq)` as its primary key and a unique terminal-outcome index per call ID. Direct duplicate-sequence appends surface `ConcurrentAppend`; terminal tool outcomes cannot be silently duplicated in the same journal.
- HISTORY: commit `15dce4f2ec1cafb13b12e3010858323e1c409e28` is explicitly titled “Fail closed on ambiguous tool outcomes.” The inspected head `3d4c3bf58b4262cf523e78655ff0bf1c9453830e` then added the model-backed planner with tests designed so the model cannot weaken replay or approval invariants; its commit message says the suite grew from 33 to 48 tests.
- PROVENANCE: repository license is MIT. The repository is zero-star/zero-fork at inspection time, making it unusually low-attention relative to the specificity of the recovery semantics.

CLAIMS NOT VERIFIED / LIMITS:
- This is not distributed exactly-once execution. The SQLite implementation has no run lease/ownership epoch and the README explicitly says concurrent production workers, network partitions and multi-node scheduling are not proven. A `(run_id, seq)` uniqueness guard detects a direct append collision, but it is not sufficient evidence that two independent processes can never both reach external I/O.
- Replay does not bind the tool-handler/source version. The runtime reuses completed outcomes after restart but does not freeze a source fingerprint or prove that a changed tool implementation is semantically equivalent. Its explicit divergence guard checks a recorded tool name against the replayed decision; it is weaker than Chidori's strict source/argument replay verifier.
- Actor/evidence on manual outcome resolution are structurally required but not cryptographically authenticated or independently verified. A free-form actor string and evidence dictionary are an audit hook, not proof that the claimed remote outcome is true.
- The FastAPI control plane lacks authentication, RBAC and a production approval UI; provider integrations are application-supplied. The committed tests use deterministic fake/in-process tools, not live payment/email/provider APIs.
- The test suite was inspected, not independently rerun in this shadow run.

INDEPENDENT RED-TEAM / VERIFIER: PASS_WITH_LIMITS. The strongest commodity objection is that ambiguity-aware durable execution already exists outside this repository: mature workflow engines and at least one independent durable-tool runtime document the same principle that non-idempotent writes with unknown outcomes must become indeterminate/HITL rather than automatic retries. Therefore the value is not a novel distributed-systems theorem. The useful artifact is the compact, readable, agent-specific implementation plus regression tests that make the unsafe crash window concrete and keep approval authority outside the model. The strongest technical objection is concurrency: without a run lease or transaction spanning ownership plus effect dispatch, the repository must not be advertised as multi-worker exactly-once protection. The strongest evidence objection is provenance drift: completed effects are replayed without source fingerprints, so this is weaker as a deterministic verification fixture than Chidori. These limits lower rarity/operability but do not contradict the narrower claim that the repository implements and tests fail-closed ambiguous-outcome recovery in a single-journal agent runtime.

COMMERCIAL WEDGE: Use the semantics as a **High-Risk Agent Action Safety Adapter** rather than selling this repository as a complete orchestration platform. For one workflow that can issue refunds, credits, billing corrections, account changes, messages or other non-idempotent actions, add persist-before-act call IDs, explicit idempotency class, approval gates, completed-outcome replay and an `INDETERMINATE -> evidence-backed resolution` state. The paid deliverable is an incident-oriented safety retrofit plus crash-window tests. The economic path is avoided duplicate refunds/credits/actions and faster operator recovery from timeout/acknowledgement ambiguity. Production deployment would still require a stronger ownership/lease layer, authenticated operator identity and provider-specific status lookup.

SECOND DEEP CANDIDATE / COMPARATOR: `davccavalcante/agenticstash@b73efb4378df37de893901b9016abf6498f2474f` independently confirms that deterministic agent record/replay is becoming a reusable primitive rather than only a framework feature. Its replay engine is strict by default on input hashes, raises on exhausted recordings, reports missing/extra calls, provides fork/diff facilities, and has a tested SHA-256 tamper-evident seal. The tree contains 14 test suites and the initial-release commit claims 86 tests, zero runtime dependencies and SLSA release provenance. It is stronger than `agent-runtime` as a framework-neutral replay/evidence library but does not supply crash-resume, approval or ambiguous external-write recovery. Its `onDivergence: collect` mode can execute an extra call live when a producer is supplied while still marking the report mismatched, so it should not be confused with a universally no-live verifier. Apache-2.0.

ECOSYSTEM COMPARATOR: Phrony's public durability documentation independently uses persist-before-act invocation records, explicit side-effect classes and an `indeterminate -> HITL` path for `non_idempotent_write` / `irreversible_action` after uncertain outcomes. That convergence reduces novelty credit for the pattern while increasing confidence that **ambiguity-aware side-effect recovery** is a real emerging runtime requirement rather than an idiosyncratic design choice.

VALUE HANDOFF:
1. CAPABILITY DELTA: the production architecture gains a precise failure-state primitive missing from ordinary replay: `STARTED + NO AUTHORITATIVE OUTCOME + NON_IDEMPOTENT => INDETERMINATE/HOLD`, never “retry because no success row exists.”
2. GRAPH EDGE: directly strengthens governance/approval, restart recovery and external-action evidence boundaries. It complements Chidori: Chidori is stronger on source-bound strict replay; `agent-runtime` is clearer on the external commit/acknowledgement ambiguity window.
3. RADAR SIGNAL: independent implementations now converge on two layers of agent reliability: deterministic replay for known past effects, and explicit indeterminate-state handling for effects whose remote outcome cannot be inferred from local persistence.
4. EXPERIMENT IMPACT: kill/restart tests should add a crash point immediately after external dispatch but before local success persistence. Passing requires no automatic replay for non-idempotent actions and a separate evidence-resolution path.
5. COMMERCIAL IMPACT: the most defensible buyer is an AI/application platform team exposing money-mutating or customer-visible tools. The first wedge is an action-safety retrofit, not framework migration. ROI can be measured in duplicate-action incidents prevented, ambiguous-outcome MTTR and percentage of high-risk tools covered by provider-side reconciliation.
6. NEGATIVE KNOWLEDGE: journal append uniqueness is not a run lease, “idempotent” must be a domain/provider claim rather than a casual developer label, and operator-entered resolution metadata is not itself authoritative evidence. Future candidates need an explicit source of truth for resolving ambiguity.

EFFORT: 5 materially distinct discovery/validation modes; 2 deep inspections (`prathamesh-git9/agent-runtime`, `davccavalcante/agenticstash`); 1 external ecosystem comparator; approximately 18 external research calls; 0 reproducible test executions in this run.
