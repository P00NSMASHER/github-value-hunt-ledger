HYPOTHESIS: Durable agent runtimes become materially more valuable when every external effect is forced through a recorded host boundary with strict deterministic replay, fail-loud divergence, crash resume, approval pauses, and single-writer state protection. A runtime that can turn a recorded run into a no-live-effects regression fixture should materially compress long-horizon reliability and verification engineering compared with graph/checkpoint-only frameworks.

DISCOVERY METHODS: (1) direct domain search for durable/resumable agent runtimes and checkpoint/replay systems; (2) code-level search around `checkpoint`, `resume`, `call log`, `host call`, replay divergence, approvals, strict verification, and run leases; (3) ecosystem/comparator search across deterministic-replay and workflow/runtime families, including Atmosphere's multi-runtime AI governance layer; (4) recent commit/history archaeology for reliability defects, release failures, CI hardening, and concurrency fixes. CLAIM / EVIDENCE PACKET:
- IMPLEMENTED + TESTED: durability is based on deterministic replay of an effect journal rather than only process-memory/checkpoint restoration. Host effects are deterministically keyed, live results are journaled, and restore re-evaluates the bundle while feeding prior results until the live frontier. `crates/chidori-js/src/replay.rs` explicitly detects bundle changes and treats edits to already-journaled behavior as divergence rather than silently substituting new side effects.
- IMPLEMENTED + TESTED: `crates/chidori-js/tests/replay.rs` contains concrete record→fresh-runtime replay, suspend→persist→restore→resume, post-frontier modify-and-resume, pre-frontier fail-loud divergence, memoized deterministic-step replay, and independent-restored-runtime tests. The replay test deliberately avoids re-performing previously recorded effects; the divergence test errors when an already-executed host call changes.
- IMPLEMENTED: the strict verification workflow in `docs/replay.md` requires a source snapshot manifest, disables providers/tools, uses an untrusted policy posture, refuses source drift, enables strict replay so a journal miss cannot silently execute live, ignores the lax-replay escape hatch, requires the full journal to be consumed, refuses pauses/incomplete runs, detects unexpected live calls, and checks byte-identical output. Export refuses incomplete/leased/paused runs.
- IMPLEMENTED: crash continuation preserves the original run ID, persisted host promises, approvals, VFS, signals and policy state. Server resume/signal/approve paths use a run lease and return 409 Conflict to a second writer before it mutates durable state.
- IMPLEMENTED: powerful tool/network/workspace effects are approval-gated by default; unattended untrusted execution fails closed unless the operator explicitly selects trusted mode.
- PROVENANCE: root license is Apache-2.0. The inspected head is the 2026-08-30 v3.8.1 release-fix commit.
- HISTORY / NEGATIVE EVIDENCE: the same head documents that v3.8.0 shipped npm/PyPI packages while crates.io/binary publication failed due to an engine `TypeofBr` panic plus an out-of-sync internal crate, and that main CI had accumulated unrelated failures. v3.8.1 adds regression and pre-publish drift checks, but this is evidence of a young runtime with real release-engineering risk, not a mature infallible substrate.

CLAIMS NOT VERIFIED / LIMITS:
- Distributed single-writer safety is backend-dependent. The repository documentation says run leases are advisory on filesystem and S3 stores; stronger exclusion is available on stores such as SQLite/cell-store/Durable Objects. Do not claim universal exactly-once execution from the lease feature.
- The replay guarantee only covers effects mediated through the runtime boundary. Workspace state remains real disk; recorded writes can be re-materialized during verification, and external behavior bypassing the host boundary cannot be magically replayed.
- Normal replay has an explicit `CHIDORI_REPLAY_LAX=1` compatibility escape hatch for argument divergence; the dedicated `chidori verify` path is stricter and ignores that escape hatch.
- I did not independently rerun the repository test suite. A local clone/test setup attempt was blocked by the execution sandbox's lack of outbound DNS, so TESTED means committed tests were inspected rather than rerun here.
- Production-scale throughput, multi-region durability, compatibility with arbitrary Node/Python agent ecosystems, and realized customer reliability savings were not independently established.

INDEPENDENT RED-TEAM / VERIFIER: PASS_WITH_LIMITS. The strongest commodity objection is that Temporal, DBOS, AWS durable-execution systems and agent checkpoint frameworks already solve durable workflows or resumable state. Chidori's non-commodity value is narrower: an agent-specific effect boundary plus zero-model-call deterministic replay, strict source/argument divergence, a no-live-effects CI fixture contract, human pause/resume, and explicit single-writer continuation. The thesis should therefore be “replayable agent execution and verification,” not merely “durable agents.” The strongest operational objection is the custom embedded JavaScript runtime and backend-dependent lease semantics; migration/integration burden could erase the benefit for teams already deeply invested in Temporal/LangGraph-style stacks. Recent release/CI defects lower evidence/operational confidence and prevent an unqualified PASS.

Wrap one workflow's model/tool/API effects behind the runtime boundary; deliver strict replay fixtures, crash/resume and approval-gate tests, source-drift evidence, and duplicate-driver tests. The money path is lower incident MTTR, less repeated model spend during debugging, reduced duplicate side-effect risk after crashes/retries, and faster deterministic regression testing. A first paid engagement appears feasible on a weeks-scale integration rather than requiring a full platform replacement, but customer migration cost is the gating variable.
