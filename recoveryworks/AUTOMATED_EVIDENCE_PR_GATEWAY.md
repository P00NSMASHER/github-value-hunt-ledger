# RETALLY generated-evidence PR gateway — source stage

**Not activated.** This is a software implementation for eventual use by
the Scout, Catalog Append, Integrator Sync and Technology Intelligence writer
jobs. None of the four existing scheduling, authoring or main-commit workflows
is changed in this candidate. The live main branch remains unprotected until
their replacement has been proven and the disabled ruleset can be safely
activated.

## Proposed protocol

1. Existing writer generates evidence and stages only its lane-specific
   allowlisted files. Commit once on a **new** branch derived from the exact
   main SHA: `automation/retally-<lane>-<GITHUB_RUN_ID>-<GITHUB_RUN_ATTEMPT>`.
   Never push or rebase automatically onto main.
2. `retally_automated_pr_proposal.py` validates the real remote commit's sole
   parent, exact current main SHA, unique changed-file population, allowed
   extensions/paths, no deletions, and matching GitHub runner identity.
   If valid, create a same-repository PR using the ephemeral Actions
   `GITHUB_TOKEN`, then explicitly dispatch
   `retally-generated-pr-merge.yml` **on main**.
3. That trusted controller accepts only the GitHub Actions bot and verifies
   the PR's current source repository, head, base, sole commit parent,
   allowlisted changed files and exact immutable SHAs. It dispatches
   `Repository Release Gate` on the source branch. This explicit
   `workflow_dispatch` is essential: a PR generated by `GITHUB_TOKEN`
   normally does not trigger `pull_request` workflows.
4. Wait for the same commit's **new** workflow-dispatch run and its complete
   five release jobs: AI Business OS, Freight, RecoveryWorks, Technology
   Intelligence and final release-gate. Rerun current main and PR authority
   checks after waiting. A skipped, pending, cancelled or failed job is a
   **hold**, not authorization to merge.
5. Ask GitHub to perform its normal `PUT /pulls/{number}/merge` operation
   with the original expected HEAD SHA. Do not force push, fake reviews,
   disable GitHub protections, choose a paid service or bypass customer
   evidence review.

## Failure semantics

A refused PR-creation permission, missing CI run, changed main, malformed
artifact, unexpected path, provider timeout or merge conflict leaves the
proposal **open and unmerged** for bounded reconciliation. A retry must be
source-frozen, must not overwrite or delete the original proposal, and must
never substitute CI from a different SHA.

No real scheduled worker is migrated yet. **First establish the separate,
synthetic-only Actions-token canary in PR #530 and confirm it can create a PR,
dispatch genuine CI and merge a single inert Markdown file.** The repository
setting allowing GitHub Actions to create pull requests may require owner
configuration. No personal tokens, bot PATs, stored OCI credentials or
customer records are requested or printed.

The scripts are separately testable with mocked GitHub authority responses
and contain no real-customer processing, money movement, cloud service
provisioning, claims, Access Allow policies or release activation.
